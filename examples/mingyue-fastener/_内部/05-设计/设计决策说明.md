# 设计决策说明 · 铭岳紧固件（示例）

> 产出方：设计（`b2b-ui-designer`）。读者：PM（对客解释）、前端、测试、策划。设计稿：`设计稿/home.html`（首页，桌面 1440 + 手机 390 响应式）、`设计稿/model.html`（型号页 DIN912-M6x20-12.9-BO）。
> 每条：决定 → 归因类别（业务 / 体验 / 视觉 / 技术）→ 一句理由。只有「视觉」一个归因的决定已重新审视并标注。
> 首页区块顺序（按线框，设计未改）：G-1 导航 → H1 首屏 → H2 产品分类 → H3 工艺链 + 数字（Bento，载体段）→ H4 质量与下载 → H5 中段 CTA → H6 非标按图定制 → H7 页尾 CTA → 页脚；手机加 G-2 底部粘性条。

## 一、给 PM 的三句话（客户确认时用）

1. **为什么首屏这样**：德国采购前 5 秒要看「你做什么、做到什么等级」，所以右侧不是车间大图而是一张 DIN912-M6x20-12.9-BO 参数卡——标准号、等级、公差、抗拉一眼可见；左侧一句话 + Request a Quote。首屏静态、无轮播。
2. **为什么能力总览用数字**：100% 光学全检（汽车件）、15 天出样、1.8 亿件 / 年、IATF 16949 是四个有出处的事实；图标和形容词不是证据，数字是。
3. **为什么没有轮播和弹窗**：轮播第二张起几乎没人看，弹窗是采购最反感的元素；询盘入口放在首屏按钮、证据后的中段条、页尾深底区和手机底部条四处，比弹窗更可靠。

## 四、可替换性自查

**「把公司名、logo、文案换成同行业另一家，这版设计还成不成立？」**

**结论：不成立。** 理由：这版的骨架不是版式而是这家的产品和数字——① 首屏参数卡与载体段全站只认一件产品 `DIN912-M6x20-12.9-BO`，四帧映射的是「冷镦 → 搓丝 → 自有热处理 → 光学全检」这条**这家自有**的工艺链，换成一家做自攻钉（要渗碳、无 12.9）或锚栓（不过光学筛选）的厂，第 3、4 帧和载体本身都要重画；② 色板的三个中性 / 强调色各自来自发黑、达克罗、回火稻黄，换一家不做发黑和自有热处理的厂，色板就失去出处；③ 内六角截面母题、螺纹节距分隔线来自第一品类 DIN 912，换法兰螺栓厂母题要换；④ Counter 的 100% / 15 days / 180 million / IATF 是这家的 F4 / F9 / F5，换一家数字和强调位都变。能原样套用的只剩导航条与页脚框架——那是询盘站的通用骨骼，不是这版设计的身份。

补充自检（场景段三问）：换成另一家客户的产品还成立吗 → 不成立；这个动作在客户车间真的会发生吗 → 会（F3 / F4）；采购看到会说「对，就是这么做的」吗 → 结构工程师认得冷镦 + 搓丝 + 回火 + 尺寸检，会。
