# 字段与区块说明 · 铭岳紧固件（示例）

> 产出方：前端。读者：后端（CMS 字段 / 导入模板 / 表单链路）、PM（后台手册）。
> 本 demo 为纯静态站（见 `降级说明.md`）：「字段」= `content/` 下 JSON 的键；「区块」= `src/templates/` 的模板函数。后端若迁回 WordPress，字段名可一一映射为 ACF 字段 / 分类法，本表即 CMS 字段清单。
> 字数提示按线框上限；超出不会破版（容器预留 ±20%，长串 `overflow-wrap:anywhere`），但会超过设计意图。

## 一、文件 → 页面

| 文件 | 页面 / 区块 | 模板 |
|---|---|---|
| `content/site.json` | 全站：导航、搜索框、主按钮、页脚、页尾 CTA 默认文案、公司信息、`baseUrl` | `layout.mjs` |
| `content/meta.csv` | 每页 title / description / robots（与 `04-文案/标题与描述表.csv` 同格式，按 `url` 查） | `build.mjs` |
| `content/categories.json` | 4 个分类页 + 首页分类卡 + 导航下拉 + 目录筛选 Category 值 | `catalog.mjs` |
| `content/models.json` | 型号页 + 目录表 + 分类页型号表 + 首页参数卡的来源型号 | `model.mjs` / `catalog.mjs` |
| `content/countries.json` | Contact 国家下拉（首位 Germany / United States / Poland 由 contact.json 指定） | `contact.mjs` |
| `content/pages/*.json` | 各页区块文案 | 对应模板 |

## 二、全站字段（site.json）

| 键 | 类型 | 必填 | 提示 |
|---|---|---|---|
| `name` | 文本 | 是 | 公司全称，用于 alt / JSON-LD / 页脚 |
| `wordmark` `tagline` `logoTodo` | 文本 | 是 | 字标占位；logo .ai 到后改 `layout.mjs` 的 `.logo` 为 `<img>`（36px 高，页脚 44px），删 `logoTodo` |
| `baseUrl` | URL | 是 | canonical、sitemap、JSON-LD 前缀；正式域名定后改一次 |
| `email` | 邮箱 | 是 | 全站 mailto |
| `phone` `officeHours` `timezone` | 文本 | 否 | 含 `[待确认]` 时页面显示审稿标注；D17 / D22 定「不放」则**删键并在 `layout.mjs` / `contact.mjs` 去掉整行** |
| `address.*` | 文本 | 是 | street / city / region / country / countryCode（JSON-LD PostalAddress） |
| `search.placeholder` | 文本 | 是 | `DIN912-M6x20`；搜索提交到 `/products/?s=` |
| `cta.primary` `cta.primaryHref` | 文本 / URL | 是 | 全站主按钮文案 **Request a Quote**（只此一处定义） |
| `nav[]` | 数组 | 是 | 一级 ≤ 7；`dropdown[]` 多列文字分组（title + items[label, sub, href]） |

## 六、询盘表单（给后端）

`content/pages/contact.json → form`

| 字段 name | 类型 | 必填 | 预填来源 | 校验 / 提示 |
|---|---|---|---|---|
| `name` | text | 是 | — | 空 → "Please enter your name" |
| `email` | email | 是 | — | 格式 → "Please enter a valid email address" |
| `company` | text | 否 | — | autocomplete=organization |
| `country` | select | 否 | — | 首位 Germany / United States / Poland |
| `model` | text（mono） | 否 | URL `?model=` 或 `?category=` | 标签 Standard & size |
| `quantity` | text | 否 | — | inputmode=numeric |
| `message` | textarea | 是 | `?topic=not-listed` → "Size not listed:"；`?topic=audit` → "Factory audit:" | 空 → "Please tell us what you need" |
| `attachment` | file | 否 | — | accept .pdf/.step/.stp；≤ 10MB 由接收端限制 |
| `topic` | hidden | — | URL `?topic=` ∈ quote / certificate / 3.1 / custom / not-listed / audit / fair | 默认 quote |
| `website` | **蜜罐** | — | — | 非空即丢（前端静默跳 thank-you；后端同样丢） |

- 提交行为：`<form method="post" action="/contact/thank-you/" data-endpoint="">`。JS 拦截提交 → 校验 → 蜜罐 → 按钮加载态（宽度锁定、`aria-busy`、"Sending…"）→ 若 `endpoint` 非空则 `fetch POST`（multipart）→ 成功跳 `/contact/thank-you/`，失败顶部 `role=alert` 红条并保留内容。
- **接收端未配置**（`[待确认：表单接收端]`）：提交内容暂存访问者浏览器 `localStorage.inquiry-log`（临时条目库，不是正式通道），然后跳 thank-you；**不得以此状态交 QA 测邮件到达**。后端配好 SMTP/表单服务后填 `content/pages/contact.json → form.endpoint`。
- 无 JS：浏览器原生 POST 到 `/contact/thank-you/`（静态托管多返回 405），后端需在接收端处理或改 `action`。
- Thank-you 页 `noindex, nofollow`，不进 sitemap；GA4 转化事件在此页触发（SEO / 后端接）。
