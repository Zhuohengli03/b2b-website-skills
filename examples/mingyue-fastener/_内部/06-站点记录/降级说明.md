# 降级说明 · 铭岳紧固件（示例）

> 产出方：前端。读者：测试、设计（§2 回流）、后端（§4 §5）、PM。
> 记录三类：栈的降级（§1）、设计在某断点的降级（§2–3）、功能在零素材 / 无后端条件下的降级（§4–6）。每条写：什么条件 → 降成什么 → 为什么 → 升级口。

## 1 · 栈：WordPress → 纯静态站（本 demo）

技术清单定的是 WordPress + GeneratePress / GenerateBlocks + Kadence Blocks + ACF（业务员能自己加产品）。本 demo 改为 **Node 22 零依赖静态生成**：`content/*.json` + `src/templates/*.mjs` → `build.mjs` → `dist/`。

原因：demo 环境无 PHP / MySQL / 外网，无法装 WordPress 与插件；静态站能完整呈现设计、文案、SEO 基础项与动效实现，且性能上限更高（首页 3 请求 23 KB gz）。

映射关系（迁回 WordPress 时）：

| 技术清单项 | 本 demo 实现 | WordPress 对应 |
|---|---|---|
| 自定义文章类型 product + 6 维分类法 + Ajax 过滤 | `models.json` 字段 + 浏览器端筛选（URL 参数可分享、无 JS 显示全表） | CPT + taxonomy + `admin-ajax` / REST 过滤 |
| ACF 字段组 | `字段与区块说明.md` 的键 | 同名 ACF 字段 |
| Kadence Tabs / Accordion / Counter / Advanced Form | 原生 radio+label Tabs、`<details name>` Accordion、rAF Counter、原生 `<form>` + 12 行校验 | Kadence 区块 |
| AOS | 1.2 KB IntersectionObserver 渐入 | AOS 或同一段脚本 |
| Complianz（Cookie 条） | **未实现**（本站零 cookie、零第三方脚本，暂无需同意条；GA4 接入时必须加，见 §5） | Complianz |
| 原生搜索限定 product | 导航搜索框 → `/products/?s=`，浏览器端匹配型号串 / 标准号 | `WP_Query post_type=product` |
| 批量导入 CSV | 未写（D18 数据到后 `build.mjs` 加 10 行 CSV → models.json） | WP All Import / 自写导入 |
| 后台改内容 | 改 JSON + 跑一条命令（README 有步骤） | 后台表单 |

公司自己的维护成本：静态站要求你（或以后改网站的同事）会改 JSON 并运行 `node build.mjs`；任务分派写「没人会改后台」，所以这条在真实项目里倾向 WordPress 或接 Git 托管的自动构建（Cloudflare Pages / Netlify：推送即发布，README §3 已写）。**不改技术清单，只在本记录说明。**

## 2 · 导航在 1024–1439 的收紧（回流设计，附两个替代方案）

设计稿只排了 1440 与 390。实测：6 个一级项 + 160px 搜索框 + 主按钮 + 24px 间距，在 1240 版心（内宽 1144）需要 1248px，**1440 也装不下**（设计稿里按钮溢出版心 ≈ 100px，被视口右边距掩盖）；1024 需 1350px。

已做的降级（不改 ≥ 1440 的视觉意图，只收间距）：

| 断点 | 改动 |
|---|---|
| ≥ 1024 | 导航项间距 24 → 16px；搜索框 160 → 124px（字 13px）；按钮内距 32 → 16px；字标字距 0.06 → 0.04em；`[待确认：logo]` 标注改绝对定位不占宽 |
| 1024–1279 | 再隐藏搜索框（Products 页筛选栏与手机面板仍有搜索） |
| 1024–1151 | 导航版心内距 48 → 24px；项间距 12px；字标 18 → 16px |

实测 1024 / 1100 / 1152 / 1200 / 1280 / 1366 / 1440 / 1920 均不溢出。

给设计的两个替代方案（任选其一可恢复 24px 间距）：
A. 一级项「Custom Cold-Formed Parts」缩为「Custom Parts」（−60px），下拉与页脚保留全称；
B. 搜索框改为图标按钮，点开后展开输入（−100px），或并入 Products 下拉顶部。

## 4 · 零素材与待确认数据的降级

| 位置 | 条件 | 现状 | 升级口 |
|---|---|---|---|
| 所有证据位（车间 ×3、证书 ×3、设备 ×2、产品 ×4、厂区 ×1） | 图未到 | `.placeholder` 虚线框 + 母题 + `[待确认]` + 拍摄要求，`data-placeholder` 供 QA 扫描 | 图到后换 `<img>`（webp、宽高、lazy），容器比例不变 |
| 证书 / 数据表下载 | PDF 未到 | 「PDF coming」文字 + `[待确认]`，**不放链接** | 换 `<a href download>` + 文件大小 |
| 型号页 Drawing (SVG) | — | 已可下载（`/products/{slug}/drawing.svg`，设计自绘示意，脚注注明非生产图） | 公司 2D 图到后替换 |
| 目录 / 分类 / 相关型号表 | D18 未到 | 2 个真实型号 + 8 个占位型号（来自文案稿「同类型号」模板，灰字、不可点、`[待确认：D18 同类型号]`）+ 1 行 `[待确认：D18 代表型号 3–50]` | models.json 灌数据后占位行自动消失（有页面的型号自动变链接） |
| 筛选值 | D20 未到 | 只有事实值（M6 / M8、12.9 / 10.9、Black oxide / Zinc flake），占位灰字不做复选框 | 随数据自动生成 |
| Application 维度 | 无出处 | 两个真实型号暂标 DIN912 → Machinery + Distribution、DIN6921 → Automotive + Distribution（D32） | 你确认后改 `application[]` |
| DIN 6921 型号页尺寸格 dc / k | 公称尺寸未核 | `[待确认：DIN 6921 公称尺寸，D18]`；s = 13 mm、d = M8 已填 | 核对后填值 |
| 页尾 CTA 标题（型号页、News） | 文案稿无专属文案 | 沿用首页 H7（设计 M-9 做法） | 文案回流后在 `models.json` / `news.json` 加 `ctaEnd.title` |

## 5 · 询盘链路（交后端）

- 接收端未配置：JS 把提交内容存到访问者浏览器 `localStorage.inquiry-log` 后跳 thank-you（**临时条目库，仅供页面链路测试，不是收件通道**）；页面上按钮下方有 `[待确认：表单接收端]`。
- 配置方法：`content/pages/contact.json → form.endpoint` 填 POST 地址（multipart，含 `attachment`；蜜罐 `website` 非空丢弃；`topic` 隐藏字段作分流）。无 JS 时表单原生 POST 到 `/contact/thank-you/`，静态托管会 405 —— 后端若用第三方表单服务，把 `action` 同步改成该地址。
- Cookie 同意条：本站当前无 cookie、无第三方脚本，**暂未放同意条**；GA4 接入时必须加，且手机端要叠在底部 56px 粘性条之上（`z-index` 用 `--z-sticky` 以上值，底部 offset 56px）。
- `robots.txt` 当前为上线态（Allow）；测试站公开前改 `Disallow: /`，上线时改回（上线检查表）。

## 6 · 测试覆盖的降级

- 本环境只有 Chromium headless（1194），无 Safari / Firefox / Edge、无 iOS / Android 实机；跨浏览器与实机由 QA 补测。重点关注：`<details name>` 独占（Safari 17.2+，旧版有 JS 回退）、`clip-path` 过渡（Safari 需 `-webkit-`？已用标准属性，Safari 15+ 支持）、表格首列 sticky 在 iOS 的滚动。
- 无外网：PageSpeed / Lighthouse 远程评分未跑；指标以 Playwright 实测为准（`性能报告.md`）。
