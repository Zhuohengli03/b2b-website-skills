# 参考 · 产品载体与场景段

> 出视觉方向单（G2）和首页高保真（G3）之前读。这一份决定「设计感」怎么落地，不决定用哪个组件库（那是 `b2b-site-diagnosis/references/组件与特效.md`）。

## 场景段是升级，不是必选

先把这句说清楚，免得矫枉过正：

**「照版式排好 + 每块一个入场动画」是合格的默认做法。** 大多数页面就该这样，干净、快、好维护，你和采购都没意见。**不要在不合适的题材上硬做场景段**——硬做出来的比静态页差。

场景段是**遇到合适题材时的升级**。合不合适由题材决定，判断方法见下面的两个原型。判断下来不合适，就老老实实做好静态页，在方向单里写一句「本项目不做场景段，原因是……」，这不是失职。

## 判据：拿掉那件东西，页面还成立吗

一旦决定做场景段，它就必须是结构，不能是装饰。区别在这里：

| | 装饰 | 场景段 |
|---|---|---|
| 触发 | 元素进视口 → 播一次 → 结束 | 滚动位置实时映射到状态（`scrub`） |
| 可逆 | 往回滚什么也不发生 | 往回滚原路退回 |
| 元素关系 | 各块独立 | A 的变化导致 B 的显现 |
| 图片角色 | 内容配图 | 场景的图层 / 内容的容器 |
| **拿掉动效** | **页面一模一样**（这没问题，静态页本来就这样） | **页面塌了，内容没地方放** |

最后一行是唯一需要记住的判据。**做静态页时它不适用；一旦声称在做场景段，它就是验收线。**

## 两个原型：物，或者路径

场景段有两种形态，选错原型比选错手法更致命。

| 原型 | 滚动条代表什么 | 载体是 | 例子 |
|---|---|---|---|
| **物型** | 这件东西的时间轴 | 一件标志性实物，它自己变化 | pier88 的盘子随滚动旋转，五段内容依次上盘；一颗螺丝随滚动拧进去，螺纹每进一段对应一道工艺 |
| **路径型** | 摄像机在空间里的位置 | 一条真实的动线，各段是路上的站点 | 房屋设计：外立面全览 → 拉近 → 从窗或门穿进去 → 玄关 → 客厅 → 走廊 → 吧台 → 阳台。jeskojets 的舷窗是这一型的开场（从舱内穿到舱外） |

**判断用哪一个，问一句话：这门生意里，真实的那段过程是什么？**

- 过程发生在**这件东西身上**（它被拧、被转、被折、被装配、被加工）→ 物型
- 过程是**一个人走过一段空间或流程**（带看、参观车间、产线走一遍、下单到交付）→ 路径型

### 路径型的生成器：真人是怎么带买家看的

这一条比任何设计参考都好用：**你们的业务员在现实里是怎么把这个东西展示给买家的，页面就怎么走。**

房屋设计公司的业务员会带买家看房——先在门口看外观说结构和朝向，再进门，一个空间一个空间讲。所以页面就是这条动线，**每个房间是一段，内容挂在那个房间上**。

同样的问法换到别的行业：

| 生意 | 真人怎么带看 | 页面的路径 |
|---|---|---|
| 房屋 / 空间设计 | 带买家实地看房 | 外观 → 穿门窗进入 → 逐个空间 |
| 紧固件工厂 | 带买家参观车间 | 原料 → 搓丝 → 热处理 → 电镀 → 盐雾检测 → 包装，每站挂一项能力 |
| 包装厂 | 拿一个成品箱当场拆开 | 成型箱 → 展开成刀版 → 每个面对应一项工艺 |
| 设备厂 | 打开机罩讲内部 | 整机 → 剖开 → 逐个模块 |

**注意最后两行其实是物型**——同一门生意，问法不同会落到不同原型，两个都成立时选素材撑得起的那个。

### 路径型的代价要先算

物型只要一张合格载体图；**路径型要每一站都有图**。房屋带看要每个房间的实拍，车间动线要每道工序的实拍——这是量级差别，不是多一张少一张。

所以路径型的素材判定不同：**先数站点数，再按站点数要图**，不是套那张四条门槛的载体图表。数不齐就砍站点（六站砍成三站也成立），砍到三站还不齐就退回物型或静态页。这一条要在第 0 步清点素材时就算清楚，不要到设计阶段才发现走廊那一段没有照片。

### 三个实测样本（2026-09 拆过）

| 站 | 载体 | 怎么贯穿 | 技术栈 |
|---|---|---|---|
| jeskojets.com | **舷窗** | 三屏高的 sticky 跑道，五张图层一起 `scale` 1 → 4+，窗框中间是透明椭圆，涨过视口后你就在天上了 | Webflow + GSAP + Lenis，0 个 `pin`（全靠 CSS `sticky`） |
| pier88coast.com | **一只盘子** | 盘子 sticky 钉住，随滚动旋转，盘面上依次上五段内容，右下角 `01 / 05` | WordPress + GSAP + Lenis，**连 ScrollTrigger 都没加载**，手写滚动处理 |
| faithibiza.com | 一个拱形 | 拱形随滚动张开，卡片以不同速度错位移动 | WordPress + GSAP + ScrollTrigger + Lenis，**只有 12 个触发器** |

**前两个是载体，第三个是形状。** 拱形跟谁的生意都不搭，所以跟谁的生意都不像——它是三个里最容易被换掉的那个。这个差别就是「设计感」和「设计得挺好看」的分界。

**成本的真相：贵的是素材，不是代码。** pier88 那个盘子段在 WordPress 上大概两百行；jeskojets 的开场核心是二十行。贵的是那张专门拍的正圆盘子、那五张合成的舷窗图层。**素材够，这套不用额外花钱就能做；素材不够，写多少代码都救不回来。**

## 三条判定标准

一个候选载体要同时满足三条，缺一条就退回装饰。

**一、是实物，不是抽象图形。** 舷窗、盘子、一颗螺丝。渐变、粒子、几何色块不算。
**二、跨段落存在。** 不是某一屏的插图，是从 A 段活到 B 段。盘子跨五段。
**三、承担功能。** 盘子同时是内容容器（文案写在盘面上）、进度指示（01/05）、品牌符号（金边 + logo）。拿掉它，那五段内容无处安放。

## 你给的是参考图，不是参考站

**静态长图里没有动效。** 一张网页长图能告诉你版式、配色、字体、区块顺序、留白节奏——它告诉不了你任何东西是怎么动的。照着图排版式、再给每块加个入场动画，得到的是一个**合格的静态页**（这本身没问题，见下面「场景段是升级，不是必选」）；但它不会自己变成场景段。场景段得另外推。

| 输入 | 能供什么 | 供不了什么 |
|---|---|---|
| **参考站**（能打开、能滚的网址） | 版式、配色、字体，**以及动效**——可以真去滚一遍，拆出它用了哪几个原语、钉在哪、怎么触发 | 内容与证据 |
| **参考图**（长图截图、Figma 导出、竞品页面存图） | 版式、配色、字体、区块顺序、留白密度、圆角与阴影的用法 | **动效，一点都供不了** |

拿到参考图的做法，三步：

**一、只拆静态的部分。** 区块顺序、栏宽、字号阶梯、主色辅色、留白密度、圆角与投影。这些直接进视觉系统，该抄就抄。

**二、场景段照旧走三步推导**，依据是**你们的产品**，不是这张图。**图决定长什么样，产品决定怎么动**——这两件事分开定，不要互相迁就。

**三、把推导出来的场景段套回图的版式里。** 找图里哪一段最适合承载它（通常是产品段或能力段），在方向单里写明：「这一段在你给的参考里是静态的，会让它动起来，因为〔产品动作〕。」

### 三条禁止

**不许因为图是静态的就不做场景段。** 图没有的东西不等于不该有。

**不许因为图里某个区块「看着很有设计感」就去模仿它的效果。** 你没见过它怎么动，模仿的是自己的想象——这是最容易生成出通用 AI 动效的路径。想抄动效就去要网址，要不到就按产品推导。

**不许把参考图当线框直接实现。业务规则优先于参考图版式**：首屏必须说清能做什么、每页要有询盘入口、CTA 节律。参考图跟这些冲突时**改图不改规则**，并在方向单里写明改了哪里、为什么。

### 参考图 + 没有产品素材

这是最容易做出漂亮空壳的组合，单独说。

场景段的载体必须是真实产品——没有产品，三步推导的第一步（这件产品自己会做什么动作）就是空的。硬做就是拿抽象图形当载体，前面已经写明那是最差的选项。

- **演练 / 样板**：可以用占位几何体搭出机制（`sticky` + `scrub`），但在方向单和页面上**都标明「占位，待换真实产品」**。它演示的是交互能力，不是你们的产品。
- **正式上线的站**：不做。先按 L4 的拍摄卡拿到一张产品图，再回来做。没有产品的场景段就是纯装饰。

## 载体怎么选

**没有「品类 → 载体」的对照表。** 同一个品类的两家公司，载体大概率不同：主打型号不同、采购装它的方式不同、能拍到的实物不同。查表就是同质化的开始。

三个来源交叉，通常只剩一两个候选：

**一、采购最终装进自己产品里的那一件。** 不是设备、不是厂房、不是车间大门、不是 logo。采购买的是那个零件，不是你的固定资产。
**二、出货量最大的那个型号。** 不是最贵的，不是最新的，不是老板最想推的。跑量最大的那个才是「一看就知道你在做什么」。
**三、拍得出来的那一件。** 回到上面的素材门槛。有实物、能摆平、能去背。

三条对不上就**不做载体段**，改用零素材的原语。**硬凑一个抽象图形是最差的选项**——花了工时，还是通用感。

### 推导演示（不是查表，是看推导长什么样）

下面每一行都是「某一次推导的结果」，用来示范三步怎么走。**你们的品类和这一行相同不等于抄这一行**——先按上面三个来源重新找一遍，落到同一个答案才用它。

| 产品 | 它自己会做的动作 | 载体扮演的角色 | 落成什么 |
|---|---|---|---|
| 沉头自攻螺丝 | 拧进去 | 度量尺 | 滚动驱动旋转，螺纹每进一段对应一项工艺（搓丝 / 热处理 / 电镀 / 盐雾） |
| 深沟球轴承 | 转，且由四层装配而成 | 容器 | 滚动逐层分离外圈 / 滚子 / 保持架 / 内圈，每层旁边挂一段规格 |
| 瓦楞纸箱 | 折起来 | 通道 | 滚动中从成型箱展开成刀版图，每个面对应一项能力 |
| 注塑模具 | 合模 → 开模 → 顶出 | 进度 | 三段滚动对应三个状态，右侧参数跟着换 |

同样是「圆形物体 + sticky」，轴承落成容器、螺丝落成度量尺——差别全在第三步。

## 载体图的素材门槛（硬门槛）

不满足就降级，不要拿糊图硬做——放大到 800px 就是灾难。

- 正视或俯视，**单一角度**，不是斜着拍的产品照
- 纯净背景或可干净去背（白底 / 纯色布 / 亮台）
- 短边 **≥ 2000px**
- 单一主光源，无杂物、无手、无水印
- 同一个载体只用**一张**图，不要中途换图

这一条在第 0 步清点素材时就判，不要拖到设计阶段。

## AI 能补到哪一步

**分级规则、位置表（证据位 vs 呈现位）、L1–L4 四级阶梯，全部在 `素材分级与AI补全.md`，那一份管全站所有图。** 这里只说载体图特有的两件事。

**载体图的落点通常是 L2。** 工厂几乎都有产品照，问题从来是背景乱、有手、有水印、歪着拍、微信压缩过，不是没有。AI 去背加修图十分钟解决，产品本体像素不动。

**载体图属于证据位**，所以那条硬线在这里同样成立：不许 AI 生成一颗不存在的螺丝。螺距、头型、槽型、倒角全是错的，而读者是结构工程师。

### L3 不是退而求其次

对紧固件、五金、精密件，**线稿或 CAD 载体常常比照片更好用**：

缩放不糊、旋转不穿帮｜没有打光和色温要跟全站匹配的问题｜读起来是工程不是营销，正好对上采购的期待｜**可以直接分层做爆炸图**——九大品类换的是层，不是换图

所以 L3 应该当成主动可选项摆在方向单上，不是「没办法才用」。判断依据还是回到三步推导：如果这个产品自己会做的动作是「装配 / 分层 / 剖开」，线稿本来就比照片更能演示它。

## 拿到 L4 之后：三步，不要直接降级

L4（什么都没有）的处理顺序如下。先把三步走完，走不通再降级。

### 第一步 · 先在现有素材里找

不要一发现门槛没过就去问你。先翻这几个地方，多数项目能在这里解决：

`_内部/抓取/` 旧站原图（很多工厂旧站的产品图比现在放进素材文件夹的散图大）｜产品目录 PDF 里的内嵌图（往往是印刷级的）｜阿里国际站店铺主图（平台强制白底，正好是要的）｜你手机里的原图（**注意不是微信压缩版**，从相册直接传原图）

判断标准只有一条：**放大到 800px 宽，螺纹、纹理、边缘还清楚吗。** 清楚就能用，背景乱可以抠，尺寸差一点可以描摹重制。糊了就是糊了，抠图救不回来。

### 第二步 · 你自己拍一张，照这张卡拍

拍一张载体图跟「补拍一整套车间素材」是两件事。一整套要排时间、要清场、可能要请人；**这一张是手机 15 分钟的事**，当天就能拍出来。所以这条要求**单独提、放在补拍清单第一条**，不要混在二十项里一起列——混在一起它就被拖没了。

拍摄卡原文（agent 在停点直接给你，也可以转给负责拍的同事）：

> 拍一张产品照，就一件产品，15 分钟能搞定，手机拍就行。
>
> 拍哪一件：〔跑量最大的那个型号〕
>
> 怎么拍：找一张 A2 白卡纸或者一块白布，铺在窗边的桌上。白天拍，靠窗，让光从产品侧面斜进来，不要正对太阳，**不要开闪光灯、不要用台灯**。产品放中间，手机举到正上方拍俯视，镜头对准中心别歪。手机开最高画质，不开滤镜，**不要用变焦，人走近一点**。拍七八张，每张稍微挪一下位置。
>
> 放进素材文件夹时用**原图**——从手机相册直接传到电脑，或者用邮件、网盘；别经微信转发，微信压缩过的就用不了了。
>
> 如果这个产品是亮面的（镀锌、抛光、不锈钢），在窗户和产品之间挂一张白纸挡一下，反光会柔和很多，出来好看得多。

**路径型要的是另一套拍法**（每一站一张，不是一件产品多角度）：

> 拍〔N〕张照片，每个〔房间 / 工序〕一张，手机拍就行。
>
> 拍哪几处：〔按站点逐个列出，别写「多拍点」〕
>
> 怎么拍：**每一处都站在同一个高度**（大概胸口位置），横屏，1× 主摄，不要用 0.5× 广角——广角会把空间拍变形，几张接在一起会显得不是同一个地方。白天开窗帘拍，不开顶灯和闪光灯。每处拍三张，人和杂物先清走。
>
> 传原图，别压缩。

路径型的关键不是单张多好，是**每站之间要接得上**——同一个机位高度、同一种光、同一个色调。这一条比清晰度更重要，拍的时候容易忽略，拍摄卡上要写明。

拍完自己能对的验收标准（和拍摄卡一起给）：

- 背景干净，产品边缘和背景分得开
- 产品完整在画面里，四周留一圈空
- **放大看螺纹或表面纹理是清楚的**，不是糊的
- 单张文件 ≥ 2MB，或者短边 ≥ 2000px

### 第三步 · 还是拿不到才降级

降级路径：只用零素材的原语（`clip-path` 揭示、`opacity` 逐项点亮），效果弱一档但不难看。

**但降级要留升级口。** 这一段的组件结构按有载体图来搭，图到位后**换图即可升级**，不重排版面。方向单和设计决策说明里都要写明这句：

> 这一段现在用〔零素材方案〕。如果后面拿到一张〔产品〕的俯视原图，这一段可以直接换成产品本身，位置和文字都不用动。

**为什么值得这么费劲：** 载体段是全站唯一一处你和采购都会记住的东西。二十张车间照的边际价值远低于这一张——所以在补拍清单里，它排第一。

## 到了设计阶段才发现「这个特别适合做场景段」

第 0 步判的是门槛过没过，设计在 G2 才看得出「你们的产品做载体会特别好」。两者不同步是正常的，不要因为第 0 步标了「降级」就闭嘴。

设计发现时的动作：把它写进 `素材补拍需求.md` 的**第一条**，注明「一张图，15 分钟，附拍摄卡」，并在方向单里按上面的降级 + 升级口写。**不要自己去找图，不要用图库图充数，也不要直接判死。** PM 会把这一条写进 `_内部/待用户决定.md`，在最近的停点问你。

图在第 5 步开发之前到，就升级；没到，就按降级方案上线，不影响进度。

## 场景段放哪里：工厂站不放首屏

jeskojets 和 pier88 把场景放首屏，因为它们卖的是**感觉**——私人飞行、海边晚餐。访客来之前就想好要什么，网站的任务是让他产生「就是这里」。

工厂卖的是**能力**。海外采购打开一个陌生供应商，前十秒在判断「你能不能做我要的东西」。这十秒被三屏动画占掉，他就走了。

所以：

- **首屏保持静态**——说清做什么、给出询盘入口、快。首屏内容不许靠动效才出现（爬虫和截图都拿不到）。
- **场景段放产品段或生产能力段。** 到这一屏的人已经决定要看下去了，而且这里的动效**本身就在演示产品**，比装饰品牌更有说服力。

## 没有可选手法清单

**这一节不给「六选一」的表。** 给了就等于每个项目从同一个抽屉里拿东西，跑十家公司必然撞车——那正是这一整份文件要解决的问题。

场景做法**从你们的产品推导出来**，三步。

### 第一步：这件产品自己会做什么动作

拧进去、转、折叠展开、开合、被流体穿过、贴合、点亮、被切削、堆叠、伸缩、咬合、涨紧……

**这个动作来自产品说明书、装配图和车间视频，不来自设计参考站。** 找不到就问你「这东西装上去之后是怎么工作的」——这个问题本来就在需求表里。

### 第二步：把那个动作翻译成滚动映射

技术原语是有限的，产品是无限的，所以**变化来自第一步，不来自这张表**。这张表只负责翻译，以及告诉你成本。

| 产品动作 | 滚动映射 | 技术原语 | 素材 | 代码量 |
|---|---|---|---|---|
| 转 / 拧 | 滚动驱动 `rotation` | rotate | 一张合格载体图 | ~20 行 |
| 靠近 / 推进 / 放大看细节 | 滚动驱动 `scale` | scale | 一张合格载体图 | ~20 行 |
| 穿过 / 进入 | 镂空图层放大越过视口 | scale + 透明镂空 | 分层图（贵） | ~20 行 |
| 移动 / 通过 | 滚动驱动 `x` / `y` | translate | 一张透明底 PNG | ~15 行 |
| 展开 / 拆解 / 分层 | 各层不同 `x`/`y` 偏移 | translate ×N | 分层图或抠图 | ~25 行 |
| 开合 / 遮蔽 / 揭示 | 滚动驱动 `clip-path` | clip | 零 | ~15 行 |
| 亮起 / 生效 / 逐项确认 | 滚动驱动 `opacity` / 颜色 | opacity | 零 | ~10 行 |
| 深度 / 前后关系 | 图层不同速度 | 图层错位 | 一张照片 + 抠前景 | ~15 行 |

一个场景段通常是**一个主原语加一个辅助原语**，不是把八行都用上。

#### 感受曲线与单一峰值

滚动映射定完，再按屏写一条感受曲线，写进 `设计决策说明.md`（做法参考 nateherkai/scroll-craft）：

- **每屏一行「感受 ← 画面原因」。** 例：「稳 ← 载体正视、居中、不动」「紧 ← 载体放大到出血、文字缩成一行」「松 ← 全幅车间图、大留白、无按钮」。写不出画面原因的感受是编的；写不出感受的画面是填充。
- **相邻两屏不得同感受。** 两屏都「紧」等于一屏；两屏都「松」采购会走。
- **全站只允许一处峰值。** 峰值就是载体场景段那一屏——动作幅度最大、对比最强。两处峰值互相抵消，这和「一个页面只做 1 段载体场景」是同一条规则的两种说法。
- **峰值前一屏留静。** 峰值前面那一屏不加动效、不铺大面积强调色、不放 CTA，让落差产生；静屏通常是一张参数表或一张不动的大图。
- 首屏按「工厂站不放首屏」本来就静，峰值在产品段或能力段，所以曲线通常是：静 → 起 → 静 → 峰 → 收 → CTA。

归因：业务——采购记住的是一处落差，不是一路热闹；视觉——没有静就没有峰，连续高强度等于没有强度；技术——峰值只有一处，动效脚本与载体图也只需为一处准备。

### 第三步：载体在页面上承担什么角色

同一个动作，载体扮演的角色不同，做出来完全是两回事。

容器（内容写在它上面）／取景框（透过它看别的内容）／进度（它的状态就是读到第几段）／遮罩（它遮住和露出内容）／通道（内容从它里面经过）／度量尺（它的刻度对应参数）

pier88 的盘子是**容器**，jeskojets 的舷窗是**取景框**——两个都是「圆形物体 + sticky」，观感完全不同，差别全在这一步。

**第一步 × 第三步的交叉才是这一页的做法。** 第二步只是把它写出来。

## 判定：这个场景是不是从产品推导出来的

出方向单前自己过一遍，三个问题。

**一、把载体换成另一家公司的产品，这个场景还成立吗？** 成立 → 做的是通用装饰，退回第一步。这是最强的一条判据。
**二、这个动作在你们车间或买家的使用场景里真的会发生吗？** 不会 → 编的。
**三、你们的海外采购看到会不会说「对，就是这么用的」？** 不会 → 这是给外行看的表演。

## 两条禁令

**不因为某个映射常见就避开它。** 螺丝就该转，那就转。为了「不一样」去做一个跟产品无关的动作，是把同质化换成了莫名其妙。

**不因为别的项目用过就避开它。** 同一个原语落在不同产品上本来就长得不一样——真正的防同质化是回到产品去推导，不是换手法。**不要去读其他项目的文件夹**（读取范围见 `b2b-run/SKILL.md` 的契约）。

### 允许的段数

允许 **1 段**载体场景，放在产品段或生产能力段。素材门槛不达标就降级到零素材手法，并在设计决策说明里写明降级原因。

## 骨架（载体旋转 + 分屏）

```html
<section class="scene">              <!-- height: calc(100vh * (N+1)) -->
  <div class="scene__pin">           <!-- position: sticky; top:0; height:100vh -->
    <img class="scene__object" src="screw-top.webp" alt="">
    <div class="scene__panels">
      <div class="scene__panel is-active">…品类 1…</div>
      <div class="scene__panel">…品类 2…</div>
    </div>
    <div class="scene__count">01 / 05</div>
  </div>
</section>
```

```css
.scene__pin    { position: sticky; top: 0; height: 100vh; overflow: hidden; }
.scene__object { will-change: transform; }
.scene__panel  { opacity: 0; transition: opacity .35s; }
.scene__panel.is-active { opacity: 1; }
```

```js
const N = 5, sec = document.querySelector('.scene');

gsap.timeline({ scrollTrigger: { trigger: sec, start: 'top top', end: 'bottom bottom', scrub: 1 } })
    .to('.scene__object', { rotation: 360 * (N - 1) / N, ease: 'none' }, 0);

ScrollTrigger.create({
  trigger: sec, start: 'top top', end: 'bottom bottom',
  onUpdate: s => {
    const i = Math.min(N - 1, Math.floor(s.progress * N));
    panels.forEach((p, k) => p.classList.toggle('is-active', k === i));
    count.textContent = String(i + 1).padStart(2, '0') + ' / 0' + N;
  }
});
```

三个坑：

**钉住用 CSS `sticky`，不要用 ScrollTrigger 的 `pin`。** jeskojets 全站 59 个触发器、`pin` 用了 0 次。`pin` 会往 DOM 里塞包裹层、改布局，和 Lenis 一起用容易抖；`sticky` 是浏览器原生的，交给合成器跑。

**`transform-origin` 决定镜头往哪推。** 要「穿过某个洞」就得让原点落在洞心，不一定是 `50% 50%`。

**Lenis 接管滚动后 `window.scrollTo()` 会失效**，程序化滚动用 `lenis.scrollTo()`。

## 硬约束

- 首屏内容不许靠动效才出现
- 一个页面只做 **1 段**载体场景。两段以上就不是叙事，是杂耍
- 全部包在 `@media (prefers-reduced-motion: reduce)` 里做降级：载体停在第一个状态，N 段内容改为常规堆叠
- 载体图用 `webp`，压到 300KB 以内，`fetchpriority="low"`（它不在首屏）。这是前端「单图 ≤200KB」的**唯一例外**，前端自查表里已写明，并且要排除在上传自动压缩之外
- **手机端保留场景段，只降强度**（去 blur、旋转角度减半、换低分辨率载体图），不要整段退化成静态堆叠——一半流量看不到这个站唯一的记忆点
- 动效脚本总量 100KB 以内（GSAP 核心 + ScrollTrigger 约 70KB，Lenis 约 5KB）

## 用户感知到几个动作，才是真正的预算

jeskojets 注册了 59 个 ScrollTrigger，用户感知到的只有四五个动作：推进、点亮、穿过、转动。**触发器数量不是预算，用户能说出名字的动作数才是。**

AI 生成页面最常见的毛病正好相反：十几种效果各做一点，哪个都不成立。**一页只讲一件事，把它做透。**
