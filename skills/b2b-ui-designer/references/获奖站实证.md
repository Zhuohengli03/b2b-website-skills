# 参考 · 31 个 Awwwards 获奖站的实证结论

> 2026-09-10/11 实拆 31 个 Awwwards Site of the Day，全部打开真实站点、发真实滚轮、采 `getComputedStyle` 数值、读 `performance` 资源表。下面每条结论都有站点和数字支撑，不是设计感想。
>
> 用途：出方向单前查「这个做法值不值得做、要花多少、会不会砸」。做法怎么推导仍看 `产品载体与场景段.md`。

## 一、最重要的一条：一多半的获奖站没有场景段

31 个里按原型分：

| 原型 | 数量 | 代表 |
|---|---|---|
| **无场景段**（静态版式 + 入场动画） | ~11 | mosbyfiles、stateofaidesign、oimachi、decathlon、hobro、cerebrium |
| **物型** | ~9 | aardvark（开箱）、sharplink（线框擦除）、zeroz（取景框换图）、likova（楼体常驻） |
| **路径型** | ~11 | seasats（512 帧海面飞越）、usavionix（10 章任务）、illoca、sstr（井眼轨迹） |

**mosbyfiles.com 是最硬的证据。** 拆解时在三个滚动位置逐一采样，27 个带 transform 的元素**数值完全不变**——按「拿掉动效页面还成立吗」的判据，它的动效是纯装饰。但它是 SOTD，首页 1.11 MB，案例页 481 KB。

它的记忆点来自三件不花钱的东西：**一个人人秒懂的实物隐喻（档案袋）+ 一套高饱和色板 + 100% AVIF 的图片管线**。

**结论：「没预算所以做不出好站」是假的。** 场景段是升级项，不是入场券。

## 二、钉住：CSS sticky 压倒性胜出

31 个站里，`.pin-spacer` 数量为 0 的占绝大多数——**只有 sharplink 一个真用了 ScrollTrigger 的 `pin`（4 个 pin-spacer）**。

实测的钉住方式分布：CSS `position: sticky`（zeroz 17 处、ERA 5 处、squarespace 3 处、seasats、aardvark、united-carriers 全部）｜`position: fixed`（cipher `/works`、the-watch 全站 30 个区块、trevor-noah、px-push）｜虚拟滚动（8 个，见下）｜什么都不用（paulkalkbrenner 16 个触发器 0 pin 0 sticky、kononenko、sstr）。

**squarespace 的写法是标准答案**：CSS `sticky` 负责钉住，ScrollTrigger 只负责 `scrub` 给数值。12 个触发器里 10 个 scrub、`pin` 全为 false。

**理由不是好看，是不会塌**：`pin: true` 会往 DOM 里插 `.pin-spacer` 改写文档流，脚本一挂布局就碎；CSS sticky 是浏览器原生行为，脚本挂了页面只是不动。对上线后由公司自己维护的站，这是「偶尔不好看」和「线上事故」的区别。**换一种写法而已，零成本。**

## 三、7 个获奖站在实测中根本打不开

这是本次最意外的发现。31 个 SOTD 里有 7 个（约 23%）在拆解时卡死或超过 20 秒白屏：

| 站 | 症状 | 根因 |
|---|---|---|
| cipher.tv 首页 | 卡在 "54%"，累计 74 秒不动；**57 个请求全部 HTTP 200**，console 无报错 | 加载器完成条件本身没被满足。同站 `/works` 直接访问完全正常 |
| revelatio.studio | 两次加载各 30 秒以上仍 `is-preloading`，94 张图只到 8 张 | 全量预加载门，无超时兜底 |
| hobro.digital | 约 50 秒停在 LOADING | 加载器等一个 `preload="none"` 的视频的 `readyState`——省流量的优化和阻塞渲染的遮罩互相打架 |
| aardvarkbookclub | 120 帧全部下载完成，仍停在紫底转圈 | 预加载器依赖 `requestAnimationFrame`，标签页被节流就永远不放行 |
| kononenkogroup | 第 20 秒和第 58 秒 `performance.getEntriesByType('paint')` 返回**空数组** | 用了 Nuxt SSR，HTML 里内容都在，但被 preloader 盖死 |
| the-watch | 加载屏 20 秒以上（非弱网） | 8.80 MB 未压缩 GLB |
| michaelgatt | 三次交互才看见内容：等加载器 → 点"无声进入" → 再在画布上点一次 | 多重入口门 |

**规则：工厂询盘站不设任何形式的全屏 preloader。** 首屏 HTML、文案、CTA 无条件立即渲染。真要等资源，写成 `Promise.race([资源就绪, 1.5s 超时])`。

海外采购在弱网、省电模式、后台恢复标签页的情况下，复现上面任意一条的概率都不低——而他不会等，他回去点下一条搜索结果。

## 四、虚拟滚动：8 个站用了，每个都弄坏了别的东西

用虚拟滚动（`body{overflow:hidden}`、`scrollHeight === innerHeight`、`window.scrollY` 恒为 0）的：why-zero、gionatannese、miumiu、mesh3d、likova、michaelgatt、haoqi、k95。

实测到的连带损坏：

- **分析数据全假**。cipher.tv 的 GA4 上报了一条 `en=scroll&epn.percent_scrolled=90`——而那个页面根本无法滚动，拆解时也没滚。**虚拟滚动站上的 GA 滚动深度、热图、"滚动后弹出"客服，全部不可信。**
- **锚点跳转、浏览器"返回上次位置"、回到顶部**都可能失效。
- **程序化滚动会打断动画**。sharplink 实测：用 `window.scrollTo()` 时 Lenis 与 ScrollTrigger 失同步，`clip-path` 永久卡在 `inset(100% 0% 0%)`。

**询盘站靠数据判断漏斗、靠锚点导航，装虚拟滚动等于自断。** sstr.tech 是原生滚动拿的 SOTD，省掉一个库、少一层风险。

## 五、20 条零成本工程手段

全部从实际代码里读出来的，不花钱、不加素材。

### 反垃圾与表单

**1 · 蜜罐字段（sstr）** 表单里插 `<input name="website">`，`position:absolute; left:-9999px; width:4px; height:4px; opacity:0`，加 `aria-hidden="true"` `tabindex="-1"`；提交时非空即丢。一行 HTML + 五行 CSS，不依赖服务，不影响无障碍。**上线第一周就用得上，比任何动效都值钱。**

**2 · 单字段邮箱表单（stateofaidesign）** 页尾只要一个 email + Submit。比 8 个必填字段的询盘表转化率高一个量级。

### 图片与字体

**3 · AVIF 全量管线（mosbyfiles）** 案例页 22 张图共 **463 KB**，一张 PNG/JPG 都没有。同样密度用 JPEG 要 2–3 MB。`sharp` 批处理，零授权成本，配 `<picture>` 回退 webp。**单项收益最大的技术选择。**

**4 · 先定后期效果，再定素材规格（cipher）** 首页所有图按 `?w=600&q=85&fm=webp` 取——只要 600px 宽，因为图最终要被半调点阵碾一遍。**工厂同理：产品图若要做成描边线稿或高对比黑白，手机照的画质缺陷会被效果本身吃掉，还省一半流量。**

**5 · 只用 woff2 且子集化** haoqi 用了 437 KB 的 `.ttf`（转 woff2 子集通常 30–60 KB，白送 380 KB）；cipher 首页两个字体 358 KB，占可测总量的 **47%**。英文站 `unicode-range` 限 latin。

**6 · 可变字体单文件（decathlon）** Roboto Flex 三轴（`opsz,wdth,wght`），一个文件覆盖全部字重字宽，省 4–6 个请求。

**7 · `loading="lazy"` + `srcset` + `sizes`** zeroz 实测：11 张 2880×1460 的图渲染尺寸是 `0×0`（首页根本不显示），无 srcset、`loading="auto"`，白下约 **5,400 KB**，占全站 24 MB 的 22%。三个属性、五分钟修好。

**8 · base64 data-URI 做小纹理（px-push）** 噪点/网格内联成 data-URI，省一个请求和一次往返。高延迟网络下每省一个请求都实打实。

### 打包与托管

**9 · 一次打包，不要一堆 `<script src>`** decathlon 把 GSAP + ScrollTrigger + Lenis 全打进 **1 个 250 KB JS + 1 个 CSS**，自有请求 2 个，首屏 9 请求 / 867 KB。hobro 用同样的库发了 **20 个 `<script src>`、142 请求 / 4,833 KB**。**同样的选型，请求数差 8 倍。**

**10 · 关键脚本自托管（sstr 正例 / revelatio 反例）** sstr 把 GSAP 全套放在 `/vendor/`。revelatio 的 GSAP 来自 Webflow CDN、三个核心脚本挂在 Vercel——任一不可达站就残废。**海外买家和你老板可能在完全不同的网络环境里看这个站。**

**11 · 跨域 CDN 配 `Timing-Allow-Origin`** k95 83 个请求里 60 个 `transferSize=0`，revelatio 48 个里可测字节 = 0。你拿 PageSpeed 一测会看到一半资源没数据，以为站出了问题。

**12 · 内容放 CMS（k95）** 那个看起来全 3D 手工打造的站，背后是 Strapi，运营的人能自己登录改。**前端多花哨都行，内容必须在 CMS 里，否则改一个型号参数都要动代码。**

**13 · 数字从接口取，不写死（mesh3d）** 统计数字来自一个 8 KB 的 `stats` 端点。工厂站的「出口 N 国 / 年产能」放进一个 JSON，业务员自己改。

### 可被发现性（这三条是补丁，不修就等于内容不存在）

**14 · canvas / WebGL 旁必须补 `sr-only` + JSON-LD** illoca 是正例：全站 0 个 `<img>`、1 个 WebGL canvas，但 DOM 里留着 3 段 JSON-LD、1 个 h1、11 个 h2、**3424 字符正文**，外加一个 `.sr-only` 放着被 SplitText 拆散前的标题原文。
miumiu 是反例：`body.innerText` **36 字符**、`h1` 0 个、`<a>` **0 个**、JSON-LD 0 个。视觉上是顶级作品，对 Google 和 AI 检索几乎不存在。

**15 · count-up 数字必须在 DOM 里留真值** stateofaidesign 实测 `innerText` 读出 **`0\n+\nDesigners surveyed in 60+ countries.`**，动画跑完才变 445。**一份以「445 份问卷」为公信力核心的报告，在机器眼里全站数据是 0。** 修法：`<span aria-hidden>0</span><span class="sr-only">445</span>`。

**16 · 给 canvas 渲染的图补 `role="img"` + `aria-label`（kononenko）** 那些用 WebGL 画的图，DOM 里留的是空 div 但带完整无障碍语义，读屏器和 Lighthouse 仍然「看得见」。

### 视觉省力

**17 · `mix-blend-mode: difference` 统一 logo 墙（revelatio）** 合作买家的 logo 和 CE/RoHS/ISO 认证标颜色五花八门，深色底上加这一行全部自动变单色。**省掉逐个抠图的两天美工活。**

**18 · 三层全屏固定滤镜（px-push）** `.scanlines{opacity:.25}` + `.gloom` + `.vignette`，三个 `position:fixed; inset:0; pointer-events:none`。整站 80% 的调性来自这不到 30 行 CSS。工厂站用克制版：只留 vignette + 2% 噪点。

**19 · 0.2 是个好视差系数（kononenko）** 实测严格等于 `scrollY × 0.2`（0/60/120 对应 0/300/600）。刚好让人觉得「图有生命」又不晕。3 行 JS，无需任何库。

**20 · 自写行遮罩替代付费 SplitText（kononenko）** `<span class="ln-mask">` + `overflow:hidden` 就够，省掉 GSAP 会员费。（注：GSAP 3.13 起 SplitText 已免费，这条现在是「可选」不是「必须」。）

### 帧序列专用（要做产品转台或工序序列时看这一节）

**21 · 二分加载顺序（aardvark / seasats）** 实测请求顺序是 `0, 119, 59, 29, 89, 14, 44, 74, 104…`——先首尾、再中点、再四分点。效果：**下载到 3 帧序列就已可播（只是卡），而不是「前半流畅、后半空白」。** 把 `for(i=0;i<n;i++)` 换成二分序生成器，十几行。**对海外弱网最划算的一个改动。**

**22 · 只发偶数帧（united-carriers）** 帧序列 `frame_000, 002, 004…156`，帧数和流量直接砍半。赌的是刚体运动隔帧人眼看不出——卡车能这么干，seasats 的连续海面不敢。

**23 · 组件全用 data 属性配置（aardvark）** `data-desktop-src` / `data-mobile-src` / **`data-static-src`** / `data-frames` / `data-fps` / `data-scroll-start` / `data-scroll-end`。换产品只换属性不碰代码，以后维护网站的同事自己在 CMS 里就能改。**`data-static-src` 最关键**：脚本失败、reduced-motion、爬虫抓取时显示那一张静态图，动效降级为一张图而不是一块空白。

**24 · 移动端另做竖版帧，不是缩小桌面帧（aardvark）** 桌面 1920×1080 / 32 KB，移动 **720×1280 竖版** / 20 KB。横图缩小在手机上主体只占中间一条；重新构图后主体占满屏，字节还更小。

**25 · 画质分档写进 `<html>` class（miumiu）** `<html class="desktop chrome macos ultra">`，`ultra` 是画质档。降级逻辑全落到 CSS 选择器里，JS 里不用散落 if。工厂站照抄做慢网降级：探到 `navigator.connection.effectiveType` 差就加 `.slow`，一条 CSS 关掉全站动效。

## 六、比视觉更值钱：6 个可以直接抄的业务机制

拆了 31 个站之后最该记住的是：**对询盘站来说，下面这几个交互对转化的影响远大于任何动效。**

**1 · 参数筛选器 + 询价车（likova.space，A 级写字楼招商）**
这是 31 个里唯一和工厂同构的商业模型——单价高、规格化、必须谈、不能公开价格。它的答案：
双滑块（`area[from]`/`area[to]`、`floor[from]`/`floor[to]`）+ 复选框 + 6 种排序 → 结果卡片是「面积/层高/楼层/编号 + 一张内联 SVG 线稿图」→ **每张卡片写「PRICE ON DEMAND」**→ 心形收藏做成询价车（带计数）→ 攒几个一起提交。
**工厂版**：材质 / 公差 / 起订量 / 交期做筛选；线稿图用产品照描边；「PRICE ON DEMAND」换「Request Quote」；收藏换「加入询价单（3）」。
**这一步把「看完网站」变成「攒了一车再提交」，询盘质量和完成率都涨。** 全是原生 `<input type="range">` + checkbox + JS 过滤，零第三方库，约 3 天工。
注意：**只抄它的转化页，不要抄它的首页**（6.6 MB、117 请求、虚拟滚动、67 个 fixed 元素）。

**2 · 双视图开关 GRID / TABLE（k95）**
同一批内容两种排布，用户可切。GRID = 图片卡片墙（给第一次来的）；TABLE = 纯参数对照表（型号/规格/材质/MOQ/交期，给已经在比价的采购）。
**B2B 的两类访客需求完全相反**，一个开关就都满足。纯 CSS grid ↔ table，<30 行。

**3 · 四角常驻状态条（haoqi 的形式，换成有业务价值的内容）**
它放的是时间和鼠标坐标。工厂站换成 `Shenzhen, China · GMT+8 · Mon–Sat 9:00–18:00` + `MOQ 500 pcs · Sample 7 days` + 常驻 WhatsApp/Email 按钮。
**直接解决海外采购最先问的三件事：时差、能不能找到人、起订量。** 纯 HTML/CSS，<30 行。

**4 · 车间热区导览（era-residence）**
一张全景图 + CMS 维护的热区点（坐标存百分比）。工厂版：一张车间全景（手机横拍即可）+ 6–10 个热区（CNC 区 / 焊接区 / 喷涂房 / 三坐标 / 成品仓 / 装柜区），点开弹设备型号、台数、产能。**以后维护网站的同事自己就能加设备，不用改代码。** 约 50 行 + CMS 字段。
实现巧处：热区是被缩放的图片容器的**子元素**，图往前推时热区自动跟着放大（实测 28px → 31px），一行同步代码都没写。

**5 · 同机位擦除对比（era-residence 的 BY DAY/BY NIGHT）**
两张同机位图叠放，外层 `overflow:hidden` + 动画 `width`，一条拖拽条擦除。实测它不是改 opacity，是 day 层的包裹盒 `width: 0px` / night 层 `1403px`。
**工厂版最强的一种用法：左边买家图纸、右边你们做出来的件，同一角度对齐。** 这是「能做什么」最快的证明方式。素材只需同机位拍两张，手机可完成，约 25 行。

**6 · 价格区间前置（px-push）**
正文里直接写死 "starting at $4,000/mo"，后面立刻跟两条行式 CTA。
**工厂等价物：MOQ + 打样周期 + 起订价区间直接写在正文里，后面跟 Request a Quote。** 海外采购最烦问了半天不给区间。

## 七、复现成本：这 31 个站落在哪一档

| 档 | 总量 | 站 | 工厂站能不能用 |
|---|---|---|---|
| **轻**（<1.5 MB） | mosbyfiles 首页 1.11 MB、案例页 481 KB；mesh3d 200 KB；decathlon 首屏 867 KB；era 首屏 443 KB；k95 1.03 MB | 零或少量 3D | **这一档是目标。** 海外弱网秒开 |
| **中**（2–5 MB） | cerebrium 2.30 MB；sharplink 2.32 MB；michaelgatt 2.48 MB；stateofaidesign 4.0/4.6 MB；hobro 4.83 MB；kononenko 4.81 MB | 视频或中量贴图 | 边缘。砍字体和大图后能进轻档 |
| **重**（>5 MB） | sstr 5.19 MB；miumiu **进门前就 5.97 MB**；likova 6.6 MB；px-push 7.56 MB（**单个软盘模型吃掉 5.5 MB**）；illoca 8.7 MB；usavionix **9.02 MB**；why-zero 9.99 MB；the-watch **11.38 MB**（单个 GLB 8.80 MB 未压缩）、haoqi 12.37 MB、gionatan 13.86 MB、zeroz **24 MB**、squarespace **41.4 MB** | 定制 3D / 大量视频 | **不能。** 预算差一个数量级，弱网必死 |

**3D 的账**：要做就必须 Draco + KTX2。sstr 的 GLB 上了 Draco 是 1.67 MB，the-watch 没压是 8.80 MB，压缩比一目了然。压不了就别做 3D。

## 八、给工厂询盘站的推荐组合

拆完 31 个之后，最务实的一套是把六个站的零件拼起来，**没有一件需要 3D**：

**版式隐喻** → mosbyfiles（档案袋 / 产品册 / 样品袋，手机照在这个语境里越糙越可信，统一灰度 + 纸纹 + 微旋转 ±4°）
**首屏结构与动效剂量** → sstr（视频 + 定位句 + 副文案 + CTA；整站 10 个 ScrollTrigger 只有 3 个 scrub；最重的 3D 段严格压在 **1 个视口**内且放首屏之后）
**转化机制** → likova（参数筛选 + 询价车 + PRICE ON DEMAND）
**信息架构** → stateofaidesign（满幅底色分章 + 本章目录 + 每章一条整宽 CTA + 页尾单字段表单）
**钉住骨架** → zeroz（17 处纯 CSS sticky，零 JS 零库；钉住时长 = 父容器高 − 自身高）
**反垃圾** → sstr 的蜜罐字段

**要砍的**：任何 preloader、虚拟滚动、未压缩 3D、TTF 字体、PNG 存照片、20 个 script 标签、跨域托管的关键脚本。

## 九、一条总的
