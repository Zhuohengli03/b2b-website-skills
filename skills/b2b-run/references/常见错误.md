# 常见错误与归因

（从 `b2b-run/SKILL.md` 搬出：「常见错误」整节 + 各节里解释「为什么这么做」的长段，原文未改。正文留的是规则本身，拿不准为什么这么定、或排查跑偏时读这里。）

## 常见错误

- 一次把十个 SKILL.md 全读进来 —— 上下文塞满，每个岗位都变糊
- 调策划时没把 `references/` 一起给 —— 它会自己编一套组件和字体
- 线框不标字数上限和图片数量 —— 文案和设计必然对不上，返工从这里来
- 判定没过就往下跑 —— 缺口会被下游放大，最后在测试阶段一起爆
- 停点不停，把全站做完再给你看 —— 你会一口气挑三十条意见，四个层级混在一起
- 跳过 G2 直接出首页 —— 你的结构、配色、文案、图片意见混成一团，改完是拼凑品
- 风格只按流派表查、抓手没落地 —— 一百家工厂出来同一个站，换掉 logo 给谁都能用
- 出三版首页让你挑 —— 挑出来的是拼凑品，而且三版里有两版 agent 自己都不推荐
- 过了闸的层级不提醒代价就直接改 —— 下游已做的产出悄悄作废，闸失去意义
- 把项目产出写进 `skills/` —— skill 目录只读，产出只能写在当前工作目录
- 读了兄弟项目文件夹，然后「避开上一个案例用过的风格」—— 风格只按你们公司的四项输入匹配，别的项目用过什么不是依据
- 把写给自己人的复盘当 README 交出去 —— 以后维护网站的同事看到「流水线刻意避开了默认风格」「已向你索取」会觉得在看别人的内部文件
- 忘了更新 `RUN.md` —— 续跑时无法判断跑到哪，只能重跑
- 你没给的数字自己补一个合理值 —— 一律写 `[待确认：X]`，上线前清零
- 子 agent 开始上网找资料 —— 第 0 步跑不完的最常见原因；只有研究员（第 1 步）和策划（第 2 步抓旧站）联网
- 一步逐张开几十张图、一份产出写几十 KB —— 要求做的事没有上限才慢；看图配额和篇幅上限写进每条子 agent 指令
- 把子 agent 的汇报原样贴给你 —— 你会以为有人在回复一段你没说过的话

## 为什么这么做：归因

### 子 agent 的汇报不要原样贴给用户

子 agent 报回的是写给执行器看的（「已按你说的重写」「两件事 A / B」），直接显示出来用户会以为有人在回复一段他没说过的话。执行器收到后用自己的口吻转述：这一步产出了什么、回流了什么、现在要用户定什么。给子 agent 的指令里也写明：文内的「你」只能指用户，对执行器称「执行器」，报回只列文件路径和一句话结果。

### 指令里写明这一步能不能上网

只有研究员（第 1 步）和策划（第 2 步，抓旧站）需要联网；PM、文案、设计、前端、后端、SEO、测试一律**不上网、不抓站、不搜索**，只读给它的文件。PM 第 0 步尤其如此：需求表缺什么就写进 `_内部/待用户决定.md`，不要替用户去企查查、阿里、Google 补——那是策划「最小可行诊断」的事，而且也只允许在第 2 步做。子 agent 开始上网找资料，就是第 0 步跑不完的最常见原因。

### 产品载体图不在闸二内

**闸二里只有车间或产线 5 张 + 每个主推品类 3 张 + 证书扫描件这三项。** 产品载体图**不在闸二内**，它不阻断流水线——载体图门槛的输出只有「可做场景段 / 这一段降级」两种，写进素材清单即可，不写进闸二结论、不因为它把项目停住。把载体图和闸二混在一起，会把一个车间照产品照证书都齐、只是缺一张干净产品图的公司白白卡死。

### G2 是新加的，也是最容易被跳过的一道

设计 agent 拿到 `风格与字体方向.md` 后，**先只出方向单，不出任何页面**；方向单过闸了才出首页。理由：你看到完整首页会同时对结构、配色、文案、图片提意见，四类混在一起，改完是拼凑品。方向单只有配色和字体两个变量，意见必然落在这两件事上。

### 过闸即冻结（返工纪律）

每道闸只收自己层级的意见，过了闸再回头改上一层 = 返工。G3 时你说「导航少一页」属于 G1 已确认的层级，这是结构改动，不是 G3 的意见——agent 要提醒代价（线框、文案、设计里哪些产出要重做），但要不要返工由你决定。**不冻结的话，闸就没有意义。**

### 契约 · 读：横向自由，但不出这个目录

任何 agent 都可以直接读上游任何一份输出文件——文件就在磁盘上，读不需要经 PM 汇总。

**读的范围只有两处：当前工作目录，和 `skills/`。** 不读上级目录，不读兄弟项目文件夹——别的项目的方案、别的案例用过什么风格，跟你们公司没关系，看了只会把「和上一个不一样」当成选型依据。

**代价转移到上游：产出的约束一定要写进文件。** 这是串行流水线唯一防返工的办法。线框里写明每个区块的字数上限和图片数量，文案就不会写出 800 字塞不进 300 字的格子；技术清单里写明用哪个组件库，设计就不会画一个前端实现不了的东西。**大多数「这里需要横向调用」的场景，本质是上游偷懒没把约束写下来。**

### 契约 · 写：只写自己的

这条是硬的。前端不能改文案文件，设计不能改线框文件。同一份产出有两个作者，`RUN.md` 就失去意义——续跑时分不清哪一版是准的，重跑会覆盖掉手改，整条流水线不再可复现。

### 契约 · 例外：就地微修

下游发现的是**拼写、格式、明显笔误**这类不改变语义和结构的错误，直接改并在 `RUN.md` 的回流记录里补一行「就地修正」，不必走一圈。够小的东西走流程是纯损耗。

一旦触及事实、数字、结构、措辞取向，就不是微修，走回流。

### 契约 · 调用：不指挥，可咨询

- **禁止指挥式**：让另一个岗位 agent 去改它自己的文件。这会产生环——设计让文案缩短，文案让设计加宽，两边都在等对方，而且两次改动谁先落盘决定了最终结果，不可复现。
- **允许咨询式**：起一个**只读**的同岗位 agent 问一句「这段能不能截到 40 字」，拿回建议后**由原岗位自己落盘**。省一跳，不破坏单一作者。

### 契约 · 数字：不许自己发明

**门槛、张数、天数——只能用 skill 和文件契约里已经写着的那些。** 没写的不要现造。

真实发生过的：闸二写的是「车间或产线 5 张 + 每个主推品类 3 张 + 证书扫描件」，agent 自己造了一个「3 个自然日内交齐」和「团队合影 3 张」。造出来的东西看着挺合理——问题是它不是规则里的标准，**下一次改版会造一套不一样的**。标准一变，你就没法判断这次到底缺不缺。（10 张最小素材包是规则，不算编造——它写在本文闸二和 PM SKILL 特殊情况「没有任何图」一行里。）

需要一个规则里没有的数字时：**当场问你**（按「跑到一半要问你」的三条），带上建议值让你一句话拍板；你定了就记进 `RUN.md`，本项目沿用。**不许先斩后奏，也不许写进产出当成既定标准。**

同理适用于：素材门槛见正文闸二与 PM SKILL 的素材门槛一节；什么算返工见 `b2b-project-manager/references/确认与改稿规则.md`。去读，不要算。

### 契约 · 问你：只有一个出口

九个 agent 各自问你，是你的时间被耗光的最快方式。所以要你翻资料、问老板、拍照片才能定的事，一律追加到 `_内部/待用户决定.md`，不写进自己的产出，不各自在对话里问；到停点或攒满 5 条时由 PM 汇总成一次选择题。全文见 `references/对话表.md` 末节。

### 项目目录 · 边界只有一条

**这个文件上线后还要不要留着用。** 要 → 根目录或 `交付/`；不要 → `_内部/`。交付区的文字读者是以后维护这个网站的同事（可能就是你），用「你」：不出现「流水线」「skill」「agent」「QA」「PM」「刻意避开了 X」，不出现 `skills/` `references/` `_内部/` 这些路径，不出现「已向你索取」这种第三人称。想写这些的写进 `_内部/案例复盘.md`。
