# 项目目录

（从 `b2b-run/SKILL.md`「项目目录」一节搬出，原文未改。模式 B 第一步建目录时读一次。）

模式 B 的第一件事是在**当前工作目录**下建这个结构（全部相对路径），然后把你手上的原件全部塞进 `./_内部/00-资料/`：

```
./                      交付区 —— 根目录是上线后留给公司的东西：站点源码、验收单、资产清单（文件名仍叫交付清单）、后台手册
  README.md             写给以后维护这个网站的同事（可能就是你），第二人称，零内部术语（前端写部署与运行，PM 写改内容）
  交付/                  验收单.md 交付清单.md 后台手册.md 导入模板.csv
  （站点源码、构建脚本、public/、dist/ 等，按前端选型自定）

  _内部/                 内部区 —— 建站过程文件。上线后可以整个拿掉，剩下的就是留给公司的东西
    RUN.md              运行日志，唯一的状态来源
    确认记录.md          每道闸一行，PM 写。防返工的唯一依据
    待用户决定.md        所有岗位要你翻资料、问老板、拍照片才能定的事都进这里
    案例复盘.md          复盘：为什么这么做、避开了什么、下次改版怎么改，只许写在这里
    抓取/                旧站抓取备份
    00-资料/            需求表.md、logo 源文件、照片、证书扫描
    01-需求/            需求单.md 素材清单.md 排期.md 任务分派.md
    02-研究/            研究简报.md 关键词表.csv raw/<站>/<日期>/（原始抓取留档）
    03-方案/            方案.md 站点地图与线框.md 技术清单.md 风格与字体方向.md 旧站迁移台账.csv（有旧站时）
    04-文案/            文案稿.md 事实来源表.md 标题与描述表.csv
    05-设计/            设计稿/ 视觉系统.md 组件规范.md 响应式规则.md 设计决策说明.md 素材补拍需求.md
    06-站点记录/        字段与区块说明.md 性能报告.md 前端自查表.md 降级说明.md 截图/ README-技术部分.md
                        询盘链路配置记录.md CMS字段说明.md 多语言配置.md 基础设施清单.md 上线检查表.md 交付清单-技术部分.md
    07-SEO/             SEO检查表.md 关键词落位表.csv Schema验证.md 分析配置记录.md 内容计划.md 月报模板.md
    08-测试/            测试报告.md 测试清单.md 复测记录.md 验收单草稿.md
    10-运营/            询盘台账.csv 月报-YYYY-MM.md 内容发布记录.md 外部提及记录.md
```

**边界只有一条：这个文件上线后还要不要留着用。** 要 → 根目录或 `交付/`；不要 → `_内部/`。交付区的文字读者是以后维护这个网站的同事（可能就是你），用「你」：不出现「流水线」「skill」「agent」「QA」「PM」「刻意避开了 X」，不出现 `skills/` `references/` `_内部/` 这些路径，不出现「已向你索取」这种第三人称。想写这些的写进 `_内部/案例复盘.md`。

**文件名以 `skills/文件契约.md` 为准**，这棵树只是它的摘要。扩展名也是契约：`.csv` 的不要存成 `.md`。
