# RUN.md 模板

（从 `b2b-run/SKILL.md`「RUN.md」一节搬出，原文未改。）

`_内部/RUN.md` 每完成一步就更新，它是断点续跑唯一的依据。格式：

```markdown
# <公司简称> · 运行日志

开跑：2026-09-10

## 进度
| 步 | 阶段 | 状态 | 产出 | 时间 |
|---|---|---|---|---|
| 0 | 建档 | 完成 | 01-需求/ 四份 | 09-10 10:20 |
| 1 | 研究 | 完成 | 02-研究/ 两份 | 09-10 10:45 |
| 2 | 策划 | 完成 | 03-方案/ 四份 | 09-10 11:30 |
| — | 停 ① 结构确认 | **等你拍板** | 已摆出线框 09-10 11:40 | |

## 开跑参数（起跑前问你得到的，本次运行不再变）

模式 · 项目根 · 需求表文件 · 旧站网址 · 硬节点 · 跑到哪停 · 拍板人（你本人 / 另有老板，需要转述）

## 假设清单（你没答、按默认推进的）
| 假设 | 若不成立则改为 |
|---|---|
| 客单价按 5k–2w USD 推 | 若是小额批发，产品页改为直接标价 |

待你决定：已问 N / 已答 N，详情见 `_内部/待用户决定.md`

## 回流与就地修正
| 时间 | 谁发现 | 什么问题 | 处理（回流给谁 / 就地修正） | 是否解决 |
|---|---|---|---|---|
```

`RUN.md` 只记「待用户决定 已问 N 条 / 已答 N 条」，条目本身在 `_内部/待用户决定.md`。就地微修（拼写、格式、明显笔误）在「回流与就地修正」表里补一行「就地修正」。
