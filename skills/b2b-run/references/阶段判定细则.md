# 阶段判定细则

（从 `b2b-run/SKILL.md` 阶段表「完成判定」列搬出的完整条文，原文未改。正文表里只留了一句话版，判这一步过不过之前读对应一节，别的节不用读。篇幅上限与随行 reference 以正文阶段表为准。）

## 第 0 步 · 建档（`b2b-project-manager`）

需求单 12 项全部有答案或标「待用户决定」；素材清单每项有状态、责任人一律写「你」，**产品图按品类分行计数不写总数**；**另外单独**判**载体图门槛**（单一角度、可干净去背、短边 ≥2000px、单光源无杂物）——**这一项不属于闸二、不阻断流水线**，只决定场景段做还是降级。达标记「可做场景段」；不达标**不要直接判降级**，按 `b2b-ui-designer/references/产品载体与场景段.md` 的三步走——先翻现有素材（旧站抓取原图、产品目录 PDF、平台白底主图、你手机或微信里的原图），再把「拍一张，15 分钟，附拍摄卡」放进补拍清单**第一条**，都不行才降级并留升级口。结论写进素材清单。

**第 0 步要有个底**：PM 只读需求表和 `00-资料/` 的目录清单，产出四份文件，每份一屏到两屏；需求单 12 项逐项填，没有的写「待用户决定」。不写排期以外的日历、不写话术、不复述 skill 正文。PM 第 0 步尤其不上网：需求表缺什么就写进 `_内部/待用户决定.md`，不要替用户去企查查、阿里、Google 补——那是策划「最小可行诊断」的事，而且也只允许在第 2 步做。

## 第 1 步 · 研究（`b2b-market-research`）

关键词表有量级与意图分类；研究简报含国内站 vs 本土同行的差异对照表。

## 第 2 步 · 策划（`b2b-site-diagnosis`）

站型已定；站点地图到二级；首页线框逐屏并**标明每个区块的字数上限与图片数量**；技术清单只从 `b2b-site-diagnosis/references/展示技术清单.md` 里选；风格方向注明素材是否支撑，**且含四条个性化抓手**。有旧站时另加 `旧站迁移台账.csv`（旧站每个有效 URL 一行）。

## 闸 G1 · 结构

把站点地图 + 首页线框摆给你看，等你一句「确认」。PM 在 `_内部/确认记录.md` 留一行，执行器放行前检查这一行存在。

## 第 3 步 · 文案（`b2b-copywriter`）

每个数字在事实来源表里有出处；没出处的写成 `[待确认：X]`；每段不超过线框标的字数上限；标题与描述表每页一行。

## 闸 G2 · 方向（`b2b-ui-designer` 的第一件事）

设计的第一件事，**只出方向单不出页面**：`_内部/05-设计/视觉方向单.md`（1 页）——色块+HEX与取自哪里、两个字体的真实示例、四个元件、**产品载体一项**（哪件实物、它自己会做什么动作、滚动里怎么动、放在哪一段。**你只给了静态长图 / 截图时，图供版式配色字体，动作仍从产品推导**）、参考站（取研究简报里 3–5 个同行）、一句话说明对上四项输入的哪几项。

## 第 4 步 · 设计（`b2b-ui-designer`）

**G2 方向单已过闸才能开始**；**logo 用公司原文件，不许重画**；场景段按 `b2b-ui-designer/references/产品载体与场景段.md` 的三步推导（产品动作 → 滚动映射 → 载体角色），**设计决策说明里必须写清载体是哪件实物、推导过程、以及「换成别家产品还成不成立」的自查结论**；常规组件的强度参数参照 `b2b-site-diagnosis/references/组件与特效.md`，偏离要写归因；素材不足时按降级规则走；**决策说明含「抓手落地」节（至少两条）与可替换性自查，自查结论必须是「不成立」，否则打回**。

## 闸 G3 · 设计

桌面首页 + 手机首页 + 一个内页。你攒成一份清单一次性提意见，确认后冻结。

## 第 5 步 · 前端 + 后端（`b2b-frontend-dev`、`b2b-backend-dev`，可并行）

测试站能打开；性能报告达标；**询盘表单实测收到邮件**；CMS 字段与导入模板可用。

**前端那一步多起一个评审子 agent**：首页渲染出来后、G3 前，起一个**不读源码、不读设计决策说明**的子 agent，只给它首页三档截图（`_内部/06-站点记录/截图/`）和 `b2b-site-diagnosis/references/公司分型速查与自查.md`，让它给首页 1–10 分并列出可删文字，结果附进 `前端自查表.md`；没起这个子 agent，自查表必须注明「未独立评审」。

## 第 6 步 · SEO（`b2b-seo-specialist`）

关键词落位表每页有主词；Schema 通过验证；分析配置已装。

## 第 7 步 · 测试（`b2b-qa-tester`）

P0 / P1 清零；`[待确认：X]` 占位全部清零，未清零一律记 P1。

## 第 8 步 · 验收与上线交接（`b2b-project-manager`）

验收单你自己逐项打勾；交付清单（资产清单）写明域名注册商与账号、服务器到期日、后台账号、GSC/GA4 权限、每年固定费用——全部在公司自己名下；后台手册给以后改网站的同事（可能就是你）+ 录屏；**README 与 `交付/` 零内部视角、零内部路径**——读一遍，出现「流水线 / skill / skills / references / agent / 已向你索取」任一处即不通过。

交付区的文字读者是以后维护这个网站的同事（可能就是你），用「你」：不出现「流水线」「skill」「agent」「QA」「PM」「刻意避开了 X」，不出现 `skills/` `references/` `_内部/` 这些路径，不出现「已向你索取」这种第三人称。想写这些的写进 `_内部/案例复盘.md`。

## 第 9 步 · 上线后（`b2b-growth-cs`）

Day 0 提交 sitemap；Day 7 复测表单；Day 30 出月报（读者是你 / 老板）。
