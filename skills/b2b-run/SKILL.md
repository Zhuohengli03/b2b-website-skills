# 流水线执行器

b2b-run 是调度员，不是生产者。**它自己不写方案、不写文案、不出设计、不写代码**——它只做四件事：建目录、按顺序调用岗位 skill、检查每次交接的载荷是否齐全、在该停的地方停下来。

判断力在岗位 skill 里，节奏在这里。

**称呼约定**：本文里的「你」指叫流水线跑起来的人——公司里负责建站的那个人（老板、外贸经理或业务员），网站是给你们自己公司做的。网站的受众叫「买家」或「采购方」。流水线只跟你说话。

## 固定路径

skill 根目录 = 本仓库的 `skills/` 目录。它随安装位置变化（Claude Code 插件目录、`~/.claude/skills/`、OpenClaw 的 skills 目录都可能），**只读，不写**。下文用 `skills/` 指代它；按 skill 名调用时（`b2b-project-manager` 等）由宿主自行定位，不需要绝对路径。

| 岗位 | 文件 |
|---|---|
| 项目经理 | `skills/b2b-project-manager/SKILL.md` |
| 市场研究 | `skills/b2b-market-research/SKILL.md` |
| 策划 | `skills/b2b-site-diagnosis/SKILL.md`（外加 `references/` 四份：风格与字体、组件与特效、展示技术清单、公司分型速查与自查） |
| 文案 | `skills/b2b-copywriter/SKILL.md` |
| 设计 | `skills/b2b-ui-designer/SKILL.md` |
| 前端 | `skills/b2b-frontend-dev/SKILL.md` |
| 后端 | `skills/b2b-backend-dev/SKILL.md` |
| SEO | `skills/b2b-seo-specialist/SKILL.md` |
| 测试 | `skills/b2b-qa-tester/SKILL.md` |
| 上线后增长运营 | `skills/b2b-growth-cs/SKILL.md` |
| 共同规则 | 仓库根目录的 `README-流水线总览.md`、`职责归属矩阵.md`、`文件契约.md`（文件名唯一来源） |

项目根目录：**当前工作目录**——你在 VS Code 里打开的那个项目文件夹（例如 `~/projects/acme-fasteners/`）。**skill 只读，项目产出一律用相对路径写**（`./_内部/01-需求/需求单.md`），不要往 `skills/` 里写任何项目文件。

## 三种模式

开跑前先认清是哪一种，别用错。

- **模式 A · 旧站体检**：只有一个旧站网址，还没决定要不要重做。只调 `b2b-site-diagnosis` 的「旧站体检单独跑」一节，在当前目录写一份 `旧站体检报告.md`，不建 `_内部/`、不写 RUN.md。可以抓全站（sitemap + 抓取，尊重 robots），但不出 `旧站迁移台账.csv`——301 目标要等新站结构定了才有，那是模式 B 第 2 步的事。开跑前八项不问，只问一句「目标市场是哪」，答不上就按英文国际站默认推进。**不向用户报预计时长**，要么直接出报告，要么说清卡在哪。**跑完就停，不要往下跑**，末尾只给两个选项：填需求表全量跑 / 只要这份报告。
- **模式 B · 全量跑**：需求表已填好。从第 0 步跑到第 9 步。
- **模式 C · 续跑**：项目已存在。先读 `./_内部/RUN.md` 找到上次停在哪，从那一步继续，不重跑已完成的阶段。

## 起跑前必答 · 问你

**缺东西时的第一反应是问你，不是自己猜。** 两条通道 + 假设清单，先分清是哪一条：

| 通道 | 什么进这里 | 节奏 | 落盘 |
|---|---|---|---|
| **问你（阻断）**（本节） | 一句话能答、猜错要返工整段、答案在你手里 | **当场问，必须带默认值**（「不答就按 X 推进」） | 答案写进 `RUN.md` 开跑参数或假设清单 |
| **待你决定（不阻断）** | 需要你去翻资料、问老板、拍照片，缺了不影响当前这一步 | 任何岗位追加；PM 在每个停点或攒满 5 条时在对话里整理成一次选择题问你 | `_内部/待用户决定.md`，四栏：谁问 / 缺什么 / 为什么需要 / 不定就按什么推进 |
| **假设清单** | 谁都不确定、缺了不影响当前步 | 成对记：假设什么 / 若不成立改成什么 | `RUN.md` 假设清单 |

判定顺序就一句：**先自己查文件，查不到再看这件事缺了卡不卡当前这一步。** 卡、且你一句话能答 → 当场问；不卡、但要你去翻去问去拍 → 进待你决定；谁都不确定 → 记假设。

### 开跑前一次性问完

第 0 步之前先把下面八项都落实。**能自己查的先查**，查不到或查出歧义（比如资料里有两份需求表）才问，**一次编号列出问完，不要一条一条挤**。

| # | 要落实的 | 先自己查哪里 | 查不到就问你 |
|---|---|---|---|
| 1 | 模式 A / B / C | 当前目录有没有 `./_内部/RUN.md` | 有 RUN.md 但你没说续跑 → 问是接着跑还是重开 |
| 2 | 项目根目录对不对 | 当前工作目录 | 目录里已有别的项目的东西 → 停下来问 |
| 3 | 填好的需求表在哪：`_内部/00-资料/需求表.md` | `00-资料/` 有没有需求表 | 空的、或有多份 → 问哪一份是准的 |
| 4 | 旧站网址 | 需求表里有没有 | 是翻新项目但没网址 → 问 |
| 5 | 有没有硬节点 | 需求表里有没有展会 / 买家来访 / 投广告的日期 | **一律问你**（你多半知道）；你也定不下来就记假设 |
| 6 | 素材实物在哪 | `00-资料/` 下的图片、证书扫描 | 你说有但目录里没有 → 问放哪了 |
| 7 | 跑到哪一步停 | — | **一律问**。你不指定就按「每道闸都停」 |
| 8 | **拍板人：你本人 / 另有老板（需要转述）** | 需求表里有没有写 | 查不到就问。另有老板 → 每道闸的东西按「能转述给老板看」的形式摆出来 |

答完写进 `RUN.md` 的「开跑参数」一节，之后本次运行不再重复问。

### 跑到一半要问你

三条同时满足才当场问，否则进待你决定或假设清单：

1. 答案在**你**手里，不需要你去翻资料、问老板、拍照片
2. 猜错要返工**整段**，不是改一行字
3. 一句话能答完

问的时候**必须带上默认值**——「你不答我就按 X 推进」，让你能直接回一句「按你说的」。只抛问题不给默认值，等于把停顿甩给你。你一时定不下来 → 按默认值推进，成对记进假设清单。

**边界只有一条：这个文件上线后还要不要留着用。** 要 → 根目录或 `交付/`；不要 → `_内部/`。交付区的文字读者是以后维护这个网站的同事（可能就是你），用「你」：不出现「流水线」「skill」「agent」「QA」「PM」「刻意避开了 X」，不出现 `skills/` `references/` `_内部/` 这些路径，不出现「已向你索取」这种第三人称。想写这些的写进 `_内部/案例复盘.md`。

**文件名以 `skills/文件契约.md` 为准**，这棵树只是它的摘要。扩展名也是契约：`.csv` 的不要存成 `.md`。

## 怎么调用一个岗位 skill

**优先起子 agent**：一个岗位一个子 agent，给它三样东西——该 `SKILL.md` 全文、这一阶段的输入文件路径、输出文件应该写到哪。要求它只写自己的输出文件，写完把文件路径列表报回来。

**子 agent 的汇报不要原样贴给用户。** 子 agent 报回的是写给执行器看的（「已按你说的重写」「两件事 A / B」），直接显示出来用户会以为有人在回复一段他没说过的话。执行器收到后用自己的口吻转述：这一步产出了什么、回流了什么、现在要用户定什么。给子 agent 的指令里也写明：文内的「你」只能指用户，对执行器称「执行器」，报回只列文件路径和一句话结果。

**指令里写明这一步能不能上网。** 只有研究员（第 1 步）和策划（第 2 步，抓旧站）需要联网；PM、文案、设计、前端、后端、SEO、测试一律**不上网、不抓站、不搜索**，只读给它的文件。PM 第 0 步尤其如此：需求表缺什么就写进 `_内部/待用户决定.md`，不要替用户去企查查、阿里、Google 补——那是策划「最小可行诊断」的事，而且也只允许在第 2 步做。子 agent 开始上网找资料，就是第 0 步跑不完的最常见原因。

**第 0 步要有个底**：PM 只读需求表和 `00-资料/` 的目录清单，产出四份文件，每份一屏到两屏；需求单 12 项逐项填，没有的写「待用户决定」。不写排期以外的日历、不写话术、不复述 skill 正文。

**没有子 agent 工具时**：一次只读一个 `SKILL.md`，跑完那一阶段、落盘、然后再读下一个。**不要一次把十个 skill 全读进来**——上下文塞满之后每个岗位都会变糊，这是这条流水线最常见的失败方式。

**策划与设计两步特殊**：`b2b-site-diagnosis/SKILL.md` 和 `b2b-ui-designer/SKILL.md` 都要求出清单/出方向单前先读 `references/` 里对应的那几份。子 agent 必须同时拿到被指到的 reference 文件，否则它会自己编一套组件、字体和动效。设计那一步要随行的是 `b2b-ui-designer/references/产品载体与场景段.md`、`b2b-ui-designer/references/设计令牌架构.md`，以及跨 skill 的 `b2b-site-diagnosis/references/组件与特效.md`。

**前端那一步多起一个评审子 agent**：首页渲染出来后、G3 前，起一个**不读源码、不读设计决策说明**的子 agent，只给它首页三档截图（`_内部/06-站点记录/截图/`）和 `b2b-site-diagnosis/references/公司分型速查与自查.md`，让它给首页 1–10 分并列出可删文字，结果附进 `前端自查表.md`；没起这个子 agent，自查表必须注明「未独立评审」。

**判定不通过时不要硬着头皮往下跑。** 缺什么就按下面的回流规则退回对应上游，让它补完再进下一步。缺的东西按「起跑前必答」那一节分流：**你能一句话答的当场问你**；要你翻资料、问老板、拍照片的追加到 `_内部/待用户决定.md`；谁都不确定的成对写进假设清单。**三条路都不许自己编一个填进去。**

## 两道硬闸

**闸一 · 范围声明**（在第 0 步时查）。本流水线只做 B2B 询盘站，不做在线收款的商城站。你要在网站上直接收钱 → 停下来告诉你不在范围内（建议走 Shopify 或 WooCommerce 方案），不要往下跑。

**闸二 · 素材门槛**（第 0 步清点素材时查）。询盘站要车间或产线 5 张 + 每个主推品类 3 张 + 证书扫描件。不达标 → 先逐张判 L1–L4，AI 能补的补，再给你 10 张最小素材包 + 手机拍摄指南让你自己拍；证据位仍缺就**停下来，输出补拍清单告诉你**（拍不了 → 本地摄影半天 / 三级过渡：自己拍 → 示意图 CAD 界面截图 → 授权图库仅做氛围），不自行降级整站方向，不要自己接着跑。

**闸二里只有上面这三项。** 产品载体图**不在闸二内**，它不阻断流水线——载体图门槛的输出只有「可做场景段 / 这一段降级」两种，写进素材清单即可，不写进闸二结论、不因为它把项目停住。把载体图和闸二混在一起，会把一个车间照产品照证书都齐、只是缺一张干净产品图的公司白白卡死。

## 确认闸（你拍板）· 4 道

到闸就停，把要你看的东西摆出来（另有老板拍板时，摆成能直接转述给老板看的形式），然后等你说继续。**规则全文在 `b2b-project-manager/references/确认与改稿规则.md`，判断卡不卡、什么算返工，一律去读那一份。**

| 闸 | 在第几步之后 | 你看什么 | 这一步只定什么 | 过了触发什么 |
|---|---|---|---|---|
| **G1 结构** | 第 2 步策划后 | 站点地图 + 首页逐屏线框 | 页面有没有少、顺序、首屏放什么 | 结构冻结，文案开写 |
| **G2 方向** | 第 4 步设计的**第一件事** | `视觉方向单.md`（一页纸，不是页面） | 配色、字体、气质 | 方向冻结，设计出首页 |
| **G3 设计** | 第 4 步设计完 | 首页桌面 + 手机 + 一个内页 | 版式、层级、区块排布 | 设计冻结，前端 + 后端开工 |
| **G4 验收** | 第 8 步 | 测试站全站 | 事实错误与缺陷 | 上线 |

**G2 是新加的，也是最容易被跳过的一道。** 设计 agent 拿到 `风格与字体方向.md` 后，**先只出方向单，不出任何页面**；方向单过闸了才出首页。理由：你看到完整首页会同时对结构、配色、文案、图片提意见，四类混在一起，改完是拼凑品。方向单只有配色和字体两个变量，意见必然落在这两件事上。

**过闸即冻结（返工纪律）**：每道闸只收自己层级的意见，过了闸再回头改上一层 = 返工。G3 时你说「导航少一页」属于 G1 已确认的层级，这是结构改动，不是 G3 的意见——agent 要提醒代价（线框、文案、设计里哪些产出要重做），但要不要返工由你决定。**不冻结的话，闸就没有意义。**

**每道闸都要由 PM 在 `_内部/确认记录.md` 留一行，执行器在放行前检查这一行存在**（闸 / 发出 / 发了什么 / 你的回复 / 结论）。没有这一行就当没确认过——防返工全靠它。

文案不单独设闸：把 `事实来源表.md` 的中文事实列摆给你核对即可，英文表达不由你逐句改，不阻塞下游。

## 契约

### 读：横向自由，但不出这个目录

任何 agent 都可以直接读上游任何一份输出文件——文件就在磁盘上，读不需要经 PM 汇总。

**读的范围只有两处：当前工作目录，和 `skills/`。** 不读上级目录，不读兄弟项目文件夹——别的项目的方案、别的案例用过什么风格，跟你们公司没关系，看了只会把「和上一个不一样」当成选型依据。

**代价转移到上游：产出的约束一定要写进文件。** 这是串行流水线唯一防返工的办法。线框里写明每个区块的字数上限和图片数量，文案就不会写出 800 字塞不进 300 字的格子；技术清单里写明用哪个组件库，设计就不会画一个前端实现不了的东西。**大多数「这里需要横向调用」的场景，本质是上游偷懒没把约束写下来。**

### 写：只写自己的

这条是硬的。前端不能改文案文件，设计不能改线框文件。同一份产出有两个作者，`RUN.md` 就失去意义——续跑时分不清哪一版是准的，重跑会覆盖掉手改，整条流水线不再可复现。

### 例外：就地微修

下游发现的是**拼写、格式、明显笔误**这类不改变语义和结构的错误，直接改并在 `RUN.md` 的回流记录里补一行「就地修正」，不必走一圈。够小的东西走流程是纯损耗。

一旦触及事实、数字、结构、措辞取向，就不是微修，走回流。

### 调用：不指挥，可咨询

- **禁止指挥式**：让另一个岗位 agent 去改它自己的文件。这会产生环——设计让文案缩短，文案让设计加宽，两边都在等对方，而且两次改动谁先落盘决定了最终结果，不可复现。
- **允许咨询式**：起一个**只读**的同岗位 agent 问一句「这段能不能截到 40 字」，拿回建议后**由原岗位自己落盘**。省一跳，不破坏单一作者。

### 数字：不许自己发明

**门槛、张数、天数——只能用 skill 和文件契约里已经写着的那些。** 没写的不要现造。

真实发生过的：闸二写的是「车间或产线 5 张 + 每个主推品类 3 张 + 证书扫描件」，agent 自己造了一个「3 个自然日内交齐」和「团队合影 3 张」。造出来的东西看着挺合理——问题是它不是规则里的标准，**下一次改版会造一套不一样的**。标准一变，你就没法判断这次到底缺不缺。（10 张最小素材包是规则，不算编造——它写在本文闸二和 PM SKILL 特殊情况「没有任何图」一行里。）

需要一个规则里没有的数字时：**当场问你**（按上面「跑到一半要问你」的三条），带上建议值让你一句话拍板；你定了就记进 `RUN.md`，本项目沿用。**不许先斩后奏，也不许写进产出当成既定标准。**

同理适用于：素材门槛见本文闸二与 PM SKILL 的素材门槛一节；什么算返工见 `b2b-project-manager/references/确认与改稿规则.md`。去读，不要算。

### 问你：只有一个出口

要你翻资料、问老板、拍照片才能定的事，一律追加到 `_内部/待用户决定.md`（谁问 / 缺什么 / 为什么需要 / 不定就按什么推进），**不写进自己的产出，不各自在对话里问**。到停点或攒满 5 条时**调用 `b2b-project-manager` 汇总**，在对话里整理成一次选择题问你，一次最多 5 条，每条带默认值。你的答复回填同一文件，再分发给对应岗位。`RUN.md` 只记「待用户决定 已问 N 条 / 已答 N 条」。九个 agent 各自问你，是你的时间被耗光的最快方式。

回流去处：结构性问题（导航、页面、区块）回策划；事实回 PM；措辞回文案；视觉回设计；DOM / 性能回前端；链路 / 基础设施回后端；收录回 SEO。回执必须写清位置、期望结果、至少一个替代方案——只说「做不了」的回执直接退回。

## 常见错误

- 一次把十个 SKILL.md 全读进来 —— 上下文塞满，每个岗位都变糊
- 调策划时没把 `references/` 一起给 —— 它会自己编一套组件和字体
- 线框不标字数上限和图片数量 —— 文案和设计必然对不上，返工从这里来
- 判定没过就往下跑 —— 缺口会被下游放大，最后在测试阶段一起爆
- 停点不停，把全站做完再给你看 —— 你会一口气挑三十条意见，四个层级混在一起
- 跳过 G2 直接出首页 —— 你的结构、配色、文案、图片意见混成一团，改完是拼凑品
- 风格只按流派表查、抓手没落地 —— 一百家工厂出来同一个站，换掉 logo 给谁都能用
- 出三版首页让你挑 —— 挑出来的是拼凑品，而且三版里有两版 agent 自己都不推荐
- 过了闸的层级不提醒代价就直接改 —— 下游已做的产出悄悄作废，闸失去意义
- 把项目产出写进 `skills/` —— skill 目录只读，产出只能写在当前工作目录
- 读了兄弟项目文件夹，然后「避开上一个案例用过的风格」—— 风格只按你们公司的四项输入匹配，别的项目用过什么不是依据
- 把写给自己人的复盘当 README 交出去 —— 以后维护网站的同事看到「流水线刻意避开了默认风格」「已向你索取」会觉得在看别人的内部文件
- 忘了更新 `RUN.md` —— 续跑时无法判断跑到哪，只能重跑
- 你没给的数字自己补一个合理值 —— 一律写 `[待确认：X]`，上线前清零
