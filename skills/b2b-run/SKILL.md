# 流水线执行器

b2b-run 是调度员，不是生产者。**它自己不写方案、不写文案、不出设计、不写代码**——它只做四件事：建目录、按顺序调用岗位 skill、检查每次交接的载荷是否齐全、在该停的地方停下来。

判断力在岗位 skill 里，节奏在这里。

**称呼约定**：本文里的「你」指叫流水线跑起来的人——公司里负责建站的那个人（老板、外贸经理或业务员），网站是给你们自己公司做的。网站的受众叫「买家」或「采购方」。流水线只跟你说话。

## 参考文件 · 什么时候读

子 agent 不读本文，也不读这些；这些只给执行器自己。**用到哪份读哪份，不要一次全开。**

| 文件 | 什么时候读 |
|---|---|
| `references/对话表.md` | 起跑前八项先查哪里、怎么问；三条通道全表；「问你只有一个出口」全文 |
| `references/项目目录.md` | 模式 B 建目录时读一次：完整目录树与每个文件的用途 |
| `references/阶段判定细则.md` | 每步判过不过之前读对应一节；含第 0 步的底、前端评审子 agent 怎么起 |
| `references/RUN模板.md` | 第一次建 `RUN.md` 或续跑时格式拿不准 |
| `references/无子agent时.md` | 宿主没有子 agent 工具时；十个岗位 skill 的路径表 |
| `references/常见错误.md` | 拿不准某条规则为什么这么定、或排查跑偏时 |

## 固定路径

skill 根目录 = 本仓库的 `skills/` 目录，随安装位置变化（见 `references/无子agent时.md`），**只读，不写**。岗位 skill 一律在 `skills/<skill 名>/SKILL.md`（名字见阶段表「调用」列），按 skill 名调用时由宿主自行定位。共同规则在仓库根目录的 `README-流水线总览.md`、`职责归属矩阵.md`、`文件契约.md`（文件名唯一来源）——**执行器读，子 agent 不读**。

项目根目录：**当前工作目录**——你在 VS Code 里打开的那个项目文件夹（例如 `~/projects/acme-fasteners/`）。**skill 只读，项目产出一律用相对路径写**（`./_内部/01-需求/需求单.md`），不要往 `skills/` 里写任何项目文件。

## 三种模式

开跑前先认清是哪一种，别用错。

- **模式 A · 旧站体检**：只有一个旧站网址，还没决定要不要重做。只调 `b2b-site-diagnosis`（随行 `b2b-site-diagnosis/references/旧站体检报告模板.md`）的「旧站体检单独跑」一节，在当前目录写一份 `旧站体检报告.md`，不建 `_内部/`、不写 RUN.md。可以抓全站（sitemap + 抓取，尊重 robots），但不出 `旧站迁移台账.csv`——301 目标要等新站结构定了才有，那是模式 B 第 2 步的事。开跑前八项不问，只问一句「目标市场是哪」，答不上就按英文国际站默认推进。**不向用户报预计时长**，要么直接出报告，要么说清卡在哪。**跑完就停，不要往下跑**，末尾只给两个选项：填需求表全量跑 / 只要这份报告。
- **模式 B · 全量跑**：需求表已填好。从第 0 步跑到第 9 步。
- **模式 C · 续跑**：项目已存在。先读 `./_内部/RUN.md` 找到上次停在哪，从那一步继续，不重跑已完成的阶段。

## 起跑前必答 · 问你

**缺东西时的第一反应是问你，不是自己猜。** 三条通道，全表读 `references/对话表.md`：**问你（阻断）**——一句话能答、猜错返工整段、答案在你手里 → 当场问，**必须带默认值**；**待你决定（不阻断）**——要你翻资料、问老板、拍照片 → 追加到 `_内部/待用户决定.md`（四栏，**每条 ≤ 3 行**），PM 在停点或攒满 5 条时汇总成一次选择题；**假设清单**——谁都不确定 → 成对记进 `RUN.md`。判定顺序就一句：**先自己查文件，查不到再看这件事缺了卡不卡当前这一步。**

**开跑前一次性问完八项**：① 模式 A / B / C ② 项目根目录 ③ 需求表在哪（`_内部/00-资料/需求表.md`）④ 旧站网址 ⑤ 硬节点（一律问）⑥ 素材实物在哪 ⑦ 跑到哪一步停（一律问，不指定就每道闸都停）⑧ 拍板人：你本人 / 另有老板。**能自己查的先查**，查不到或有歧义才问，**一次编号列出问完**；每项先查哪里见 `references/对话表.md`。答完写进 `RUN.md`「开跑参数」，本次运行不再重复问。

**跑到一半要问你**：三条同时满足才当场问——答案在**你**手里 / 猜错要返工**整段** / 一句话能答完；否则进待你决定或假设清单。问时**必须带默认值**；你定不下来 → 按默认值推进，成对记进假设清单。

## 项目目录

模式 B 的第一件事是在**当前工作目录**下建目录（全部相对路径），原件全部塞进 `./_内部/00-资料/`。根目录是**交付区**（`README.md`、`交付/`、站点源码）；`_内部/` 是**内部区**（`RUN.md`、`确认记录.md`、`待用户决定.md`、`案例复盘.md`、`抓取/`、`00-资料/` 到 `10-运营/`）。完整目录树读 `references/项目目录.md`。

**边界只有一条：这个文件上线后还要不要留着用。** 要 → 根目录或 `交付/`；不要 → `_内部/`。交付区用「你」，零内部术语、零内部路径。**文件名以 `skills/文件契约.md` 为准**，`.csv` 的不要存成 `.md`。

## 子 agent 通用指令

一个岗位一个子 agent。**它只拿自己需要的**：下面这段照抄，尖括号按阶段表填（随行 reference 列精确文件名，不是整个 `references/`）。

```
1. 你是 <岗位>，只读下面列出的文件；文内「你」指用户，对执行器称「执行器」。
2. 读：skills/<skill 名>/SKILL.md；这一步的随行 reference：<按阶段表「随行 reference」列，精确文件名>；输入文件：<按阶段表「读」列，列出路径>。
3. 不读 README-流水线总览.md、文件契约.md、职责归属矩阵.md——执行器已把输入输出路径写在这里。
4. 契约四条：只读列出的文件 / 只写列出的输出：<按阶段表「写」列，列出路径> / 不直接问用户，缺什么追加到 _内部/待用户决定.md（谁问 / 缺什么 / 为什么需要 / 不定就按什么推进，每条 ≤ 3 行）/ 不调用别的岗位，上游缺口写回执（位置、期望结果、至少一个替代方案）。
5. 本步能否上网：<是/否>。看图配额：<下面三行原话>。每份产出上限：<按阶段表「写」列的行数>。
6. 写完报回：文件路径列表 + 一句话结果 + 回流条目（如有）。不复述 skill、不贴正文。
```

**看图配额原话**（第 5 行照抄；给要看图的步：第 0 步素材清点、第 2 步旧站体检与品牌资产、第 4 步素材分级、第 5 / 7 步截图自查）：
- 先用文件名、尺寸、字节数筛，再开图。能用 `file` / `identify` / 元数据判的（短边 ≥2000px、格式、大小）不开图。
- 每个品类最多开 3 张；证书每种只开 1 张且只在判级或事实核对需要时开；宣传片 / 视频截图最多开 5 张；载体图候选先按元数据筛，最多开 5 张。
- **一步总共不超过 20 张**。超过配额的写「未逐张核，按元数据判」，不是错。

**上网**：只有研究员（第 1 步）和策划（第 2 步，抓旧站）联网；其他岗位一律**不上网、不抓站、不搜索、不装东西**。**子 agent 的汇报不要原样贴给用户**——执行器用自己的口吻转述产出了什么、回流了什么、要用户定什么。**没有子 agent 工具时**：一次只读一个 `SKILL.md`，跑完落盘再读下一个，读 `references/无子agent时.md`。

## 两道硬闸

**闸一 · 范围声明**（在第 0 步时查）。本流水线只做 B2B 询盘站，不做在线收款的商城站。你要在网站上直接收钱 → 停下来告诉你不在范围内（建议走 Shopify 或 WooCommerce 方案），不要往下跑。

**闸二 · 素材门槛**（第 0 步清点素材时查）。询盘站要车间或产线 5 张 + 每个主推品类 3 张 + 证书扫描件。不达标 → 先逐张判 L1–L4，AI 能补的补，再给你 10 张最小素材包 + 手机拍摄指南让你自己拍；证据位仍缺就**停下来，输出补拍清单告诉你**（拍不了 → 本地摄影半天 / 三级过渡：自己拍 → 示意图 CAD 界面截图 → 授权图库仅做氛围），不自行降级整站方向，不要自己接着跑。

**闸二里只有上面这三项。** 产品载体图**不在闸二内**、不阻断，只决定「可做场景段 / 降级」，写进素材清单（理由见 `references/常见错误.md`）。

## 确认闸（你拍板）· 4 道

到闸就停，把要你看的东西摆出来（另有老板拍板时，摆成能直接转述给老板看的形式），然后等你说继续。**规则全文在 `b2b-project-manager/references/确认与改稿规则.md`，判断卡不卡、什么算返工，一律去读那一份。**

| 闸 | 在第几步之后 | 你看什么 | 这一步只定什么 | 过了触发什么 |
|---|---|---|---|---|
| **G1 结构** | 第 2 步策划后 | 站点地图 + 首页逐屏线框 | 页面有没有少、顺序、首屏放什么 | 结构冻结，文案开写 |
| **G2 方向** | 第 4 步设计的**第一件事** | `视觉方向单.md`（一页纸，不是页面） | 配色、字体、气质 | 方向冻结，设计出首页 |
| **G3 设计** | 第 4 步设计完 | 首页桌面 + 手机 + 一个内页 | 版式、层级、区块排布 | 设计冻结，前端 + 后端开工 |
| **G4 验收** | 第 8 步 | 测试站全站 | 事实错误与缺陷 | 上线 |

**G2 最容易被跳过**：先只出方向单，不出任何页面。**过闸即冻结**：每道闸只收自己层级的意见，过了闸再改上一层 = 返工——agent 提醒代价，返不返工由你定。理由见 `references/常见错误.md`。

**每道闸都要由 PM 在 `_内部/确认记录.md` 留一行，执行器在放行前检查这一行存在**（闸 / 发出 / 发了什么 / 你的回复 / 结论）。没有这一行就当没确认过——防返工全靠它。PM 写这一行时随行 `b2b-project-manager/references/确认与改稿规则.md`。

文案不单独设闸：把 `事实来源表.md` 的中文事实列摆给你核对即可，英文表达不由你逐句改，不阻塞下游。

## 契约

条文在这里，全文与归因在 `references/常见错误.md`「归因」。

- **读**：横向自由，可直接读上游任何输出；范围只有当前工作目录和 `skills/`，不读上级目录、不读兄弟项目。**产出的约束一定要写进文件**（线框标字数上限和图片数量，技术清单写明组件库）。
- **写**：只写自己的。前端不改文案文件，设计不改线框文件。
- **就地微修**：拼写、格式、明显笔误直接改，`RUN.md` 回流记录补一行「就地修正」；触及事实、数字、结构、措辞取向走回流。
- **调用**：不指挥（不让别的岗位改它的文件），可咨询（起**只读**同岗位 agent 问一句，由原岗位落盘）。
- **数字**：门槛、张数、天数只用 skill 和文件契约里写着的；没有的 → **当场问你**带建议值，定了记进 `RUN.md`。**不许先斩后奏，不许写进产出当标准。** 什么算返工见 `b2b-project-manager/references/确认与改稿规则.md`。
- **问你只有一个出口**：`_内部/待用户决定.md`，不写进产出、不各自在对话里问；停点或攒满 5 条时**调用 `b2b-project-manager` 汇总**成一次选择题（≤ 5 条，带默认值），答复回填同一文件再分发。

**回流去处**：结构性问题（导航、页面、区块）回策划；事实回 PM；措辞回文案；视觉回设计；DOM / 性能回前端；链路 / 基础设施回后端；收录回 SEO。回执必须写清位置、期望结果、至少一个替代方案——只说「做不了」的回执直接退回。

## RUN.md

每完成一步就更新 `_内部/RUN.md`，它是断点续跑唯一的依据。四节：进度表（步 / 阶段 / 状态 / 产出 / 时间）· 开跑参数（起跑前八项的答案，本次运行不再变）· 假设清单（假设 / 若不成立则改为）+ 一行「待你决定：已问 N / 已答 N」· 回流与就地修正表。模板读 `references/RUN模板.md`。
