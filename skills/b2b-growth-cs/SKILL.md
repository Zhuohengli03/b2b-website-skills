# B2B 网站上线后增长运营

网站上线不是结束，是你开始判断“这个站到底能不能带来询盘”的起点。这个岗位的工作是让你在 3–6 个月里看到两条曲线：曝光和询盘在涨，网站问题在一天内响应。这两条曲线决定网站是资产还是摆设。

上游是 PM（交付清单、验收单、公司背景）、SEO（内容计划、月报模板、关键词落位表）、后端（询盘链路记录、监控邮箱）。下游是策划（回流的结构性问题）、PM（新页面 / 新功能的需求整理）。

## 你在这个环节会遇到什么、背后是什么问题、怎么处理

| 你的原话 | 背后的问题 | 怎么处理 | 归因 |
|---|---|---|---|
| “上线一个月了一个询盘都没有” | 焦虑，怀疑网站没用 | 先查硬伤（noindex、收录、链路），再给 GSC 曝光曲线和时间线；把“本月做了什么、下月做什么”写清 | 业务：可见的进展比焦虑有用，也是判断要不要调方向的依据 |
| “有询盘但都是垃圾 / 印度小买家 / 推销” | 询盘质量问题 | 分析来源与内容：表单加国家 / 数量 / 用途字段过滤；FAQ 与产品页写清 MOQ 和交易条件；博客选题转向目标市场的采购问题；反垃圾升级 | 业务：写清门槛让低质询盘自我筛掉；体验：真采购不介意多填两项 |
| “有流量没询盘” | 承接问题 | 看 GA4 行为流：落在哪页、停留多久、有没有到产品页、CTA 点击率；常见原因是首屏定位不清、产品页无参数、CTA 不显眼、手机端表单难用；回流策划 / 文案 / 设计 | 业务：流量是入口，承接是网站的活；体验：找问题靠数据不靠猜 |
| “我们没人写英文文章” | 内容执行断档 | 每月 1 次 30 分钟，agent 访谈你或公司的技术 / 业务员（录音或文字），整理成 2–4 篇；选题从收到的询盘问题来；你只审事实 | 业务：公司的工程知识是内容的唯一来源，写作由 agent 完成 |
| “想发 LinkedIn / Facebook 但没精力” | 想要社媒引流但没精力 | 每月从博客拆 4–8 条社媒帖（带网站链接），LinkedIn 为主；agent 只做内容拆分与草稿，不替你回复和谈单，边界写清 | 业务：社媒是冷启动最快的流量源；风险：别指望社媒代替询盘承接 |
| “网站要加个功能 / 加几页” | 需求增长 | 小改（改文字、加产品、换图）按后台手册自己改；新页面、新功能、新语言回 PM 走需求整理，结构改动回 G1，agent 报出下游哪些产出要重做 | 业务：分清日常维护和返工，别让小改演变成重做 |
| “网站打不开了 / 被黑了” | 事故 | 1 小时内响应；按后端的备份恢复流程处理；事后给原因与预防措施 | 风险：事故响应速度决定丢多少询盘 |
| “有个买家是从网站来的，成交了” | 好消息 | 把成交询盘的路径反查出来（来源页、关键词、哪篇内容）并强化；写进月报；经买家同意请他留一句评价放网站 | 业务：成交路径是最可靠的选题与投入依据 |

## 工作流程

### 1. 上线当周：从前面各步拿到的文件

从 PM 拿交付清单（资产清单）、验收单、公司背景（在意什么、拍板人）；从 SEO 拿内容计划与月报模板；从后端拿链路记录并确认监控邮箱能收到每条询盘副本。设置监控：GSC 每周看、GA4 转化每周看、Uptime 监控、表单条目每日看。给你一页“上线后第一个月会发生什么”的说明，把 3–6 个月时间线写清，免得一个月没询盘就推翻方向。

上线当周跑一次 **AI 可见度基线**（简版）：从关键词落位表取 10–20 条采购会问的问题（best X supplier / X manufacturer in China / X MOQ / X vs Y / X price per unit），分别在 ChatGPT（开联网搜索）和 Perplexity 各问一次，记录三列：是否引用了你的站（是 / 否）、被引用的是哪家（同行名与 URL）、AI 答案里提到的差异点。存成一张表放进当月月报「AI 可见度」一节，以后每月同一批问题复测一次。归因：业务——这是你和老板最直观能看懂的「AI 推荐了谁」证据，也是 GEO 内容与外部提及的选题来源（被引用的同行页面就是要对标的页）。

### 2. 询盘承接与追踪（持续）

每条询盘记录：日期、来源页、国家、产品、数量、质量评级（A 明确需求 / B 需要引导 / C 垃圾）、是否已回复、结果。每周过一遍 A/B 类询盘的跟进状态；48 小时还没回复的询盘，agent 提醒你。质量数据每月汇总，指导内容选题和表单过滤。

### 3. 内容执行（每周）

按 SEO 内容计划：每周 1–2 篇博客（选题优先来自本月询盘中的问题）、每月一篇对比文、每月更新一个分类页；发布后内链到产品页；拆成社媒帖。每季度回顾哪些文章带来了询盘，加倍做那类。

### 4. GEO 与外部提及（每月）

行业目录与供应商名录登记、行业协会页面、Reddit / Quora 相关问题下的真实回答（不硬广）、YouTube 工厂视频（你用手机拍，agent 整理脚本与字幕）、LinkedIn 文章。记录每条提及的链接。

每月复测一次 AI 可见度（同第 1 步那批 10–20 条问题，不换题，才能比）：引用数变化、新被引用的页面、仍被引用的同行；被引用的同行页面拆一下它的段落结构与数字，回流给 SEO 作下月选题与分类页更新的依据。

### 5. 月报（每月固定日）

读者是你 / 老板。固定结构，一页：

```
# [公司名] 网站月报 — [月份]

## 本月数据
GSC：曝光 / 点击 / 平均排名 / 收录页数（对比上月）
GA4：访问 / 来源占比 / 询盘转化数 / AI 来源访问
询盘：总数 / A/B/C 分布 / 主要国家 / 主要产品

## 本月做了什么
内容（篇数与标题）/ 外部提及 / 修复与优化

## AI 可见度
本月复测：问题数 / 引用本站的条数（对比上月）/ 被引用的同行 Top 3 / 新增被引用的本站页面

## 发现与建议
数据里看到的问题（例如某产品页停留高但无询盘）与对应动作

## 下月计划
内容选题 / 需要你提供的（访谈时间、素材、成交反馈）
每条动作四件套：观察到什么 / 依赖什么 / 怎么知道它失败了 / 看哪个领先指标

## 问题响应记录
本月响应的网站问题（打不开、改坏、事故）与处理时间
```

「下月计划」每条必带四件套，替代纯任务清单（与 SEO 的 `月报模板.md` 一致）：

| 字段 | 写什么 | 例 |
|---|---|---|
| 观察到什么 | 本月数据里的具体现象，带数字 | 「hex bolt DIN 933 曝光 1,200、点击 9，CTR 0.75%，低于站均 2.1%」 |
| 依赖什么 | 你的素材、哪个岗位、多少时间 | 「文案改分类页首段 + 你补 2 张实拍」 |
| 怎么知道它失败了 | 一个月后的否定条件 | 「下月该页 CTR 仍 < 1.5%」 |
| 看哪个领先指标 | 下月先动的数，不是询盘 | 「该页 CTR 与平均排名；AI 可见度复测是否新增引用」 |

归因：业务——你和老板能据此判断时间花在哪、哪条线该停；体验——四格比一段话更好扫读；也是回头看「做了什么、起没起作用」的原始记录。

## 为什么这么做：归因

- 业务：上线后的持续运营决定网站是资产还是摆设；用数据判断投入，不凭感觉
- 体验：你和老板每月看得懂的一页报告，比后台仪表盘有用
- 风险：事故响应、改后台改坏的回滚、买家评价的授权
- SEO / GEO：内容持续与外部提及是排名与 AI 引用的复利

示例：

| 决定 | 归因 | 理由 |
|---|---|---|
| 询盘按 A/B/C 分级并每周对账 | 业务 | 没人跟进的询盘等于白做，也是月报的核心数据 |
| 博客选题来自本月询盘问题 | 业务 + SEO | 真问题带真询盘，也最容易被 AI 引用 |
| 月报一页且有“下月计划” | 体验 + 业务 | 你看得完，且知道时间在往哪花 |
| 小改自己按手册改、结构改动回 PM | 业务 + 风险 | 日常维护不该变成返工，结构改动要有人拍板 |

## 输出格式

- 询盘台账（表格）
- 内容发布记录与社媒拆分
- 外部提及记录
- 月报（含问题响应记录）

## 交接与验收标准

每月月报按时出且含下月计划（每条带四件套）与 AI 可见度复测；询盘台账每周更新；事故 1 小时内响应、24 小时内恢复或给出方案。

## 流水线接口（作为独立 agent 运行时）

**对用户说话**：把他当技术小白。只说三类话——做到哪了（一行）、要他定的业务选择（每条带默认值，最多 5 条）、下一步他做什么（一行）；不出现执行器、模式、契约、回流、岗位名、闸编号、文件路径这些内部词。除了业务选择不停；用户说「继续」「开跑」就做下一步，不解释「这一岗不能往下跑」。

**契约**：只收下面「输入」列出的文件，收不到上游的完整对话；只写下面「输出」列出的文件，不改别人的产出；不各自问你：所有要你补的东西一律追加到 `_内部/待用户决定.md`，由 PM 汇总一次问完，一次最多 5 条；不横向调用其他岗位 agent，发现上游缺口按「回流」写回执，由 PM 调度。本步不上网、不抓站。

**输入**：PM `交付清单.md`、`验收单.md`、`需求单.md`（公司背景）；SEO `内容计划.md`、`月报模板.md`、`关键词落位表.csv`、`分析配置记录.md`（GSC / GA4 权限记在这里）；后端 `询盘链路配置记录.md`（监控邮箱）。

**输出**：`询盘台账.csv`（表格类，行数不限）、`内容发布记录.md`（表格类，行数不限）、`外部提及记录.md`（表格类，行数不限）、`月报-YYYY-MM.md`（≤ 60 行）。

**交接载荷**（缺项即视为未交接，下游可直接退回）：

- → PM：新页面 / 新功能的需求线索（你的原话 + 涉及哪些页面）。
- → 各建站岗位：零询盘诊断结论要指明是哪一层的问题（流量层 / 结构层 / 文案层 / 链路层），附对应数据（曝光、点击、停留、表单提交、邮件到达），不笼统说「没效果」。
- → SEO：收录或排名异常的具体 URL 与 GSC 截图。

**参与深度**：完整版：3–6 个月内容执行、询盘台账、月报、GEO 提及。

**完成判定**：按月循环，无“完成”；每季度回顾哪些内容带来了询盘（见第 3 步），据此调整下季度投入。

**回流**：“有流量没询盘”的结构性问题 → 策划 / 文案 / 设计；链路或性能问题 → 后端 / 前端；收录与排名异常 → SEO；新页面 / 新功能 → PM。

## 特殊情况处理

| 情况 | 怎么判断 | 怎么办 |
|---|---|---|
| 上线后仍然没图、内容做不出来 | 占位图还在、你三个月没补过素材 | 建立“每月 15 分钟”制度：固定一次，agent 问你或公司的工程师 / 业务员 3 个问题（本月最常被问什么、一个刚交付的订单、一个工艺细节），录音或文字整理成 2–4 篇；同时你当月用手机拍 5 张车间或发货照（横屏原图）补进来，逐步替换占位图，替换记录写进月报“本月升级” |
| 询盘没人跟进 | 台账里 A/B 类询盘 48 小时无回复 | agent 在台账标记并提醒你；确认邮件模板可以由 agent 拟好、你授权后代发；连续两周没跟进，月报如实写“询盘 X 条，跟进 Y 条”，并把“谁负责回询盘”写进 `_内部/待用户决定.md` 让拍板人定 |
| 三个月零询盘怎么排查 | 台账为空 | 按排错顺序（noindex → 收录 → 标题 → 链路 → 流量落点）查一遍硬伤，出一页“零询盘诊断”；确认无硬伤后给两条路：内容加密度（每周 2 篇 + 外部提及）或小预算广告测词（承接页先过策划审）；不安抚，不归咎市场 |
| 买家案例和评价写不出来 | 买家不肯具名、不给数据 | 案例写成“行业 + 问题 + 怎么解决 + 买家一句话”，一句话由 agent 拟三版写进 `_内部/待用户决定.md`，你选一版找买家确认；买家不授权就匿名（a German fastener distributor）；不编买家名与数字 |
| 负责网站的人换了（你离职 / 换同事） | 联系人变更 | 用后台手册做一次 30 分钟交接（网站能做什么、后台怎么改、当前数据、资产清单里的账号与到期日），交付清单再过一遍；变更记进月报 |
| 你或同事改后台改坏了 | 前台错版、页面打不开 | 1 小时内用备份回滚，再把“怎么改不会坏”补进后台手册；同一操作改坏三次以上，建议该项改为 agent 代改并写进月报 |
| 想让 agent 全量代运营社媒或代回复询盘 | 超出这条流水线的范围 | 边界写清：agent 做内容拆分与草稿，回复买家的价格问题和谈单必须你本人来；社媒全量运营不在这条流水线里 |
| 询盘全是垃圾或推销 | C 类占比 > 70% | 表单加国家、数量、用途字段与国家过滤，FAQ 写清 MOQ 与交易条件；一个月后复盘 A/B 类占比 |
| 没精力继续做内容运营 | 连续两个月内容发布记录为空 | 切到“最低维持”：只保主机、安全、备份与季度检查，月报改季报；把“恢复内容运营的触发条件”写进 `RUN.md` 假设清单 |
| 老板或同事说“网站做得不好” | 第三方评价 | 把具体意见记下来，逐条对照数据与规则（是硬伤就修，是偏好就写明理由），写进 `_内部/待用户决定.md` 让拍板人定，不争辩 |
| 网站被黑或宕机 | Uptime 报警、你或买家反馈 | 1 小时内响应，按后端的恢复流程回滚，24 小时内给原因与预防措施；事故写进月报问题响应记录 |

## 常见错误

- 上线后没人看表单条目，漏回的询盘没人发现
- 月报只有数字没有动作
- 下月计划是任务清单，没写观察、依赖、失败条件和领先指标
- AI 可见度每月换一批问题，前后没法比
- 博客选题拍脑袋，不看询盘问题
- 小改和结构改动不分，加页面不回 PM 直接动结构
- 觉得没效果时只焦虑不查硬伤
- 成交询盘不反查路径、不请买家留评价
- 把“有流量没询盘”归咎于市场，不回流结构问题
