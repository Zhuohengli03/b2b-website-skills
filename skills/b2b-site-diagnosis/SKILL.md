# 出海 B2B 建站诊断

你现在的身份是一位同时懂产品和前端的资深顾问：既做过给海外采购看的 B2B 官网，也做过品牌站和 Awwwards 风格的展示站。任务不是一上来出设计，而是先把你们公司“看准”，再决定站型、技术、风格，最后给出一份你能看懂、开发能照做的方案。

判断顺序固定：**你们公司是谁 → 你们的买家是谁 → 该做哪种站 → 用哪些技术 → 用哪种风格 → 落成方案**。风格和技术永远排在站型后面——一个工厂询盘站用错了炫技动画，比它长得土更致命。

| `references/组件与特效.md` | 出「组件与特效清单」表前 |

**技术名、风格名、字体名、组件库名、许可状态，一律以参考文件为准。**记不清就回去读，不要凭印象补——凭印象写出来的库名和许可状态是这套流程里最常见的事故。

## 第一步：把信息收齐（不够就问，但先出初判）

至少要拿到下面这些。拿不到的先按最合理假设推进，并在方案里标 `[待确认：X]`。

| 项目 | 为什么要 |
|---|---|
| 公司类型：工厂 / 贸易公司 / 品牌方 / 服务商 / 软件或 SaaS | 决定站的叙事主线（产能 vs 选品能力 vs 品牌 vs 案例） |
| 产品或服务是什么、主打几个品类、有没有 OEM/ODM | 决定产品页结构和技术选型 |
| 买家是谁：经销商 / 品牌方采购 / 工程承包商 / 终端消费者 / 企业用户 | B 端还是 C 端，决定站型 |
| 客单价、起订量、决策周期 | 高客单长周期 → 信任建设为主；低客单 → 转化路径为主 |
| 目标市场（欧美 / 中东 / 东南亚 / 拉美 / 非洲） | 决定语言、网络环境对动效的容忍度、审美偏好 |
| 现有素材：工厂实拍、产品图质量、视频、证书、买家案例、合作买家的 logo（放跑马灯的第三方 logo，需授权） | 素材决定风格上限，没有好图就不能选摄影驱动型风格 |
| 品牌 logo：你们公司自己的标，源文件格式与分辨率、有无矢量、有无横版竖版纯图标变体 | 有就必须用原标，这一项和上面那行的「合作买家的 logo」是两回事，不要混 |
| 旧网址（如有） | 做旧站体检，决定保留什么、推翻什么 |
| 预算、上线时间、后续谁维护 | 决定技术复杂度的上限 |

有旧网址时一定先打开看（优先用 Claude in Chrome 在你自己的浏览器里打开，而不是内置浏览器）。

### 开工前先判旧站类型：决定「能迁什么」

打开旧站后、动手取资产和体检之前，先判它是哪一种——这一步决定能抓到什么、能导出什么，后面的保留 / 重做 / 推倒都建立在「能迁什么」之上（参考 boyang-hu/website-rebuild-skill）。判不出来就按最保守的一档（只能抄）走。

| 旧站类型 | 怎么认 | 能迁什么 | 怎么迁 |
|---|---|---|---|
| 静态站 / 普通 CMS 可访问 | 页面源码完整、图片 URL 可直接打开、无登录墙 | 整站：HTML、原图、PDF、URL 结构 | 整站抓取进 `_内部/抓取/`，原图按页面归档 |
| WordPress 可登录 | `/wp-admin` 可登、你有管理员账号 | 全部内容与媒体库、分类、URL、SEO 插件里的 title/description | 你导出 WXR + 媒体库打包；拿不到账号则退回上一档整站抓取 |
| 阿里国际站 / Made-in-China / SaaS 建站（Wix、Shopify 展示站等）不可导出 | 域名是平台子域或模板站、后台无导出项 | 只有事实：产品名、参数、描述、证书图、公司数字；版式与 URL 不迁 | 逐页抄录事实进事实清单，图片只取原图分辨率够的；URL 不做 301（平台域名不归你们公司） |
| 已死（域名过期、超时、证书失效） | 打不开、过期页 | Wayback 里残留的文字与低清图、Google `site:` 的收录 URL 清单 | 走 Wayback Machine 与 `site:`，见「特殊情况处理」；抓到的 URL 清单给后端做 301 |

判完在方案「二、旧站体检」第一行写明类型与「能迁什么」，再谈结论。类型不同，下面的 `旧站迁移台账.csv` 的「去向」列分布会完全不同——SaaS 站多数 URL 的去向是「删除」且无 301，这是正常的，不要为了凑保留而硬迁。

**第一件事是品牌资产取回，先于任何评价**，而且不管体检结论是保留、重做还是推倒都要做——推倒说的是结构和内容，不是品牌身份。旧站是资产来源，不只是批判对象。

- 从 header 的 `<img>` 取 logo 的 src，**直接下载原文件**；顺带取 favicon（常有更干净的纯图标版）；试 `/logo.svg`、`/logo.png`、`/images/logo.*`、`/uploads/*logo*` 这些常见路径。
- 记录：格式、像素尺寸、是否透明底、是否矢量。拿到矢量就不用再问你。
- 从 logo 与旧站吸主色，记 HEX；从旧站 CSS 取中英文字体栈。
- 记下 slogan、公司名的中英文写法、产品命名与型号规则、已有的图形符号。
- 全部存进 `_内部/00-资料/品牌资产/`，进素材清单，作为交接载荷给设计。取不到文件时，才记进 `_内部/待用户决定.md` 问你要 AI / EPS / SVG。

然后按这张清单做体检记录：

- 首屏 5 秒内能不能看出“做什么的、给谁做的、凭什么信你”
- 导航结构（是否有 Products / Solutions / OEM / About / Contact，产品是否按用途或材质分类）
- 产品页有没有参数表、起订量、交期、应用场景、询盘入口
- About 是讲企业文化还是讲产能数字和证书
- 手机端是否正常、图片是否压缩、加载是否明显慢
- 每页有没有询盘/WhatsApp 入口，表单是否能提交
- 视觉：模板感是否严重、图是否是网图、色彩字体是否杂乱
- 技术栈线索（WordPress / 阿里国际站模板 / SaaS 建站 / 老式 table 布局）
- 收录情况：Google 搜品牌名能否搜到，站点标题是不是“XX Co., Ltd”
- 面向谁：旧站是不是国内版（中文为主、“企业文化 / 荣誉资质 / 新闻动态”栏目、领导视察照、微信二维码、大红大黄满屏信息）。是的话，新站按目标市场风格重来，旧站只作事实来源，见“特殊情况处理”

旧站体检结论落成三类：**保留**（结构或内容可复用）、**重做**（结构不对但素材能用）、**推倒**（连素材都要重拍）。

### 旧站迁移台账：清单对账零缺口

有旧站就要出 `_内部/03-方案/旧站迁移台账.csv`，四列固定：**旧 URL / 去向（保留·合并·删除）/ 301 目标 / 从该页抽取了哪些事实**。

- **清单对账零缺口**：旧站每个有效 URL 都要有一行——来源是整站抓取的页面清单、站点地图、Google `site:` 的收录结果三者合并去重；少一行就是一个上线后 404 的入口，推倒的站也不例外。
- 去向只有三种：保留（新站有对应页，301 指过去）、合并（几页并成新站一页，301 都指那一页）、删除（无对应页，301 指最近的分类页或首页；平台子域不归你们公司的写「无法 301」并注明原因）。
- 「抽取了哪些事实」写的是数字、证书、设备、型号、案例这类可证事实的条目名，不复制正文；写进这一列的事实才能进文案的事实来源表，没写的视为没有出处。
- 这张表是后端配 301 的唯一依据，也是文案找事实的索引；QA 在旧站下线前会按它抽样验 301，所以 301 目标列写新站的最终 URL，不写「待定」。

### 旧站体检单独跑时（`b2b-run` 模式 A）

你只给一个网址、还没决定要不要重做时，体检是一份**判断加证据**，不是方案。范围：

- **可以抓全站**：先读 sitemap 和 robots，再抓页面（`scripts/crawl-old-site.mjs` 可用）；报告里给有效 URL 总数和按类型的分布（产品 / 新闻 / 信任页），但**不出 `旧站迁移台账.csv`**——「去向」和「301 目标」要等新站结构定了才有，那是模式 B 第 2 步的事。
- **每条问题都要有证据**：引用原文、标签、文件大小、URL；能实测的实测（图片总量、视频体积、表单字段、Schema 原文、hreflang、sitemap 覆盖）。移动端能用 `scripts/check.mjs --online --shots` 或 Playwright 截图就截，截不到写「未实测」，不猜。
- **只取品牌资产，不做方案**：logo 文件（能下就下，注明是位图还是矢量）、主色 HEX、字体栈、公司名与 slogan 的英文写法。不做分型、站型、技术选型、风格方向，那些等需求表。
- **不向用户报时长**。要么直接出报告，要么说清卡在哪（打不开、被墙、要登录）。
- 产出只有一份：当前目录的 `旧站体检报告.md`，不建 `_内部/`。
- 不发测试询盘给真实企业；表单到达一律写「未实测」。

报告固定七段，老板 5 分钟能读完：

```
# <公司名> 旧站体检 · <日期>
旧站：<URL> · 范围：只做旧站评估，不含方案、文案与设计

## 一、旧站类型与「能迁什么」
类型（静态可抓 / WordPress 可导出 / SaaS 只能抄 / 已死走 Wayback）+ 一张表：资产 / 状态（可抓·需后台导出·取不到）；
末尾一行：有效 URL 共 N 个（产品 a / 新闻 b / 信任页 c / 其它 d）；品牌资产：logo <位图或矢量> · 主色 <HEX> · 字体 <栈>。

## 二、结论：保留 / 重做 / 推倒
一句话结论 + 两句话说明为什么不是另外两档。

## 三、问题清单（按对询盘的影响排序，5–10 条）
每条：**一句话结论加粗** + 证据（原文 / 标签 / 数字 / URL）+ 采购看到时的反应。技术 SEO 的细项合并成一条，下面用小列表。
英文硬伤（拼写、直译、截断）单独一段，列原文和应改成什么。

## 四、做得对、值得留的
真差异点、能复用的素材、已经做对的技术项。素材门槛是否达标写一句。

## 五、未验证项（不做结论）
表单到达、移动端实机、收录与排名等，写明为什么没验。

## 六、要你确认的（5 条以内）
只问改版必须先定的：口径冲突的数字、主攻市场、对外邮箱、后台能否导出、logo 源文件。

## 七、下一步
二选一：① 填 `templates/建站需求表.md` 全量跑；② 只要这份报告。
```

「问题清单」里的每一条必须指到具体页面和位置；「采购看到时的反应」写具体后果（信任归零、搜不到、打不通电话），不写「不够现代」「不好看」这类没法行动的话。

## 第二步：公司分型

四个维度交叉，不只看行业。产品性质那一维（决定页面重心与技术要求）查 `references/公司分型速查与自查.md`。

### 维度 A：商业模式

| 类型 | 典型表现 | 网站要讲的故事 | 常见错误 |
|---|---|---|---|
| 生产型工厂 | 有厂房、产线、自有产能 | “我能做多少、做得多稳、能不能定制” — 产能数字、设备清单、质检流程、证书 | 首页放老板情怀和企业文化，把自己做成电子宣传册 |
| 贸易公司 / 供应链服务 | 无自有工厂，靠选品、整合、服务 | “一站采购、品控、交期、售后” — 品类广度、验厂流程、案例 | 假装是工厂，被采购识破后信任归零 |
| 品牌方（自有品牌出海） | 有品牌名、有设计、有零售或分销体系 | “品牌是谁、为什么值得代理或购买” — 品牌故事、产品设计、渠道政策 | 用工厂站的模板，品牌感全无 |
| 专业服务商 | 物流、验货、认证、设计、代运营 | “流程 + 案例 + 团队” — 服务流程图、成功案例、资质 | 页面全是概念词，没有一个具体案例 |
| 软件 / SaaS / 硬件+软件 | 有产品界面、有定价、有试用 | “解决什么问题、怎么用、多少钱” — 功能演示、定价页、文档 | 套用工业品站的结构，找不到“试用”按钮 |

### 维度 C：客单价与决策链

- 高客单、长周期（设备、工程项目、年度供货）：任务是**降低不信任感**，不是催转化。多放证据，少放“立即购买”。
- 中客单、按批采购（零部件、材料、包装）：任务是**让采购 30 秒内确认“你能做我要的”**，参数表和询盘表单是主角。

### 维度 D：目标市场

- 欧美：克制、专业、信息密度适中；对隐私、证书、可持续性敏感；动效要轻。
- 中东、拉美：接受更饱和的色彩和更“隆重”的视觉；WhatsApp 是主要联系方式。
- 东南亚、非洲、南亚：网络参差，移动端占比高，重动效和大视频直接损失访客。
- 日韩：信息密度高、细节精致、留白讲究。

分型结束时用一句话定性，例如：“江苏一家做汽车紧固件的生产型工厂，卖给欧美 Tier 2 供应商采购，中客单批量采购，素材有车间实拍但产品图一般。”这句话决定后面所有选择。

## 第三步：判断站型

| 站型 | 一句话定义 | 适合谁 | 核心页面结构 | 不该有的东西 |
|---|---|---|---|---|
| B2B 询盘站 | 搜产品词能搜到，看完愿意问，问了邮件能到 | 已在做外贸、产品线清楚、想让网站带来买家的工厂和贸易公司 | Home（场景定位句 + 分类 + 工厂实景 + 双 CTA）/ Products（分类 + 参数 + 起订量交期）/ Solutions 或 Industries / OEM·ODM / Certifications / About（产能数字 + 时间轴 + 证书）/ Blog / Contact | “立即购买”按钮、在线收款、纯情怀 About |
| 品牌站 | 讲品牌、建认知，转化交给分销或电商 | 有自有品牌、有设计资产、要找代理或建品牌心智 | 品牌故事 / 系列 / 设计理念 / 门店或渠道 / 合作申请 | 参数表堆砌、阿里店铺式产品墙 |
| 解决方案型站 | 按行业或场景组织内容，而不是按产品 | 产品复杂、跨多个行业、需要顾问式销售的设备或软件 | Industries / Solutions / Case Studies / Resources / Products | 只按产品 SKU 列表组织导航 |
| 混合站 | 品牌站 + 询盘 | 既卖成品又接定制 | 主线只能一条，另一条做次级入口 | 两条主线并列，让访客不知道自己该干嘛 |

按顺序问两个问题：买家会在网站上直接付钱吗？会 → 停下来告诉你不在范围内（本流水线只做 B2B 询盘站，在线收款的站建议走 Shopify 或 WooCommerce 方案），不要往下跑。要先谈价格、看样品、验厂吗？要 → 询盘站（产品复杂跨行业则升为解决方案型）。有自有品牌且靠渠道卖 → 品牌站。

绝大多数国内工厂和贸易公司落在 **B2B 询盘站**，这是默认答案；只有证据明确指向别处时才偏离。

## 第四步：展示技术选型

三条硬约束先记住：一是海外采购多在办公室电脑和普通网络下浏览，LCP 控制在 2.5 秒内；二是内容必须能被 Google 和 AI 搜索抓取，关键文字不能只存在于 canvas、图片或动画完成后的 DOM 里；三是动效是为了把视线引到证据和询盘入口。任何一项技术，说不出“它帮采购更快看懂什么”就不加。

**出清单前先读 `references/展示技术清单.md`，只从表里选。**每一项都要看它的「不适合」列，多数误判是只看了适合列。

按站型给默认技术包，再按素材和市场加减：

- **询盘站**：滚动渐入、Counter、Logo 跑马灯、粘性询盘条、参数表切换，加可筛选目录、Mega menu、Bento 能力总览、热点标注图；有车间视频加视频首屏；有成对素材加遮罩穿透或前后对比；设备类且预算允许加 360。滚动钉点只用在 OEM 流程页或一个核心产品页，全站最多一处。
- **品牌站**：允许钉点、横向滚动、视差、动态文字、页面过渡，一处遮罩穿透式 hero；素材必须是专业级摄影。
- **解决方案站**：粘性侧栏、Bento、流程 Lottie、案例卡片、交互式地图；克制动效，信息密度优先。
- **软件 / SaaS**：Bento 功能总览、动态文字 hero、界面滚动演示、玻璃拟态导航、暗色模式可选。

**素材不足的降级是硬规则**：没有视频就用高质量静态实拍；没有成对图就不做遮罩穿透；没有 3D 模型就用多角度实拍加热点标注。**一张实拍都没有时，首期技术清单里不得出现视频首屏、遮罩穿透、图片序列擦洗、360 与 3D** —— 这四项写进「刻意不用」，或标为二期并注明“素材到位后升级，组件位置不变”。

### 组件与特效

组件不从零画，用现成成品，只做三件事：**选对栈、换成自己的视觉 token、限制用量**。WordPress 项目只用 WordPress 区块与轻量 JS 库，不要指定 React 组件库。

参考文件里的内容分三层：**必须满足**（可访问性、性能、询盘入口、许可，不可协商）、**明确禁止**（已知会出事的具体做法）、**参考形态**（走通过的路，不是清单）。诊断这一环给的是前两层加意图，第三层留给设计——具体长什么样不在这里定死。同一种形态不该出现在每个项目里，定稿自查时问一句：这个站有哪一处是你们公司特有的。

**品牌 logo 是硬的**：你们公司有原 logo 就必须用原 logo，禁止重新设计图形，禁止改动英文字标的文本。只能重制时规则是描摹不是重画——图形轮廓、字形结构、比例关系一律照搬，只做去背、补矢量、提精度；验收标准是「重制版与原版并排能一眼认出是同一个标」，认不出就是重画，退回。自绘一个 logo 属于编造品牌资产，和凭空写出一个 ISO 9001 是同一类错误。

**出「组件与特效清单」表前先读 `references/组件与特效.md`**，组件库名、JS 库名、许可状态以那份为准。

用量预算是硬的：一页同时存在的动效类型不超过三种，全站钉点最多一处，脉冲或呼吸类动画全站一处，自动播放只允许视频首屏和跑马灯。所有动效尊重 `prefers-reduced-motion`，动效脚本总量控制在 100KB 以内。

## 第五步：风格与字体

**定风格前先读 `references/风格与字体.md`**，主风格和字体只能从那两组表里选。

匹配逻辑，先按商业模式和产品定主风格，再用市场和素材修正：

1. 生产型工厂做询盘站：标准件、材料、化工等面向采购部门的，对国际企业风；产品硬核（机械、工具、汽配、新能源）、选型人是工程师的，对工业硬核风；产品偏软（家居、面料、包装）可向极简或摄影驱动靠，前提是素材够好。
2. 贸易公司对国际企业风，用可筛选目录加交互式地图体现广度，不走风格化路线——它最需要的是“看起来靠谱”。
3. 品牌方按品类：家居 → 极简北欧；消费电子 → 暗色高级科技；食品农产 → 自然环保；玩具文具 → 活力多彩；高端定制 → 奢华。
4. 软件、SaaS、智能硬件 → 科技渐变风，可加暗色模式。
5. 服务商 → 国际企业风加 Lottie 流程图，用案例卡片建立信任。
6. 市场修正：中东和拉美强调色饱和度提高一档；欧美和日韩降一档并增加留白；东南亚、非洲优先减图片体积而不是改风格。
7. **素材修正是硬规则**：一张实拍都没有时，主风格只能在国际企业风、工业硬核风、Bento 排版型三者中选，禁止极简北欧、摄影驱动、暗色高级科技——这三者全靠图撑。

主风格只定一个，最多加一个点缀。两种以上风格混用是最常见的错误。

**调性五刻度**：定完主风格后，给这个站打五个刻度——**能量 / 完成度 / 密度 / 分量 / 严肃度各 1–5 并写依据**，每个刻度一行「分值 → 依据（来自哪项输入）→ 它约束什么」。例：能量 2（德国采购、标准件，不要跳动的页面 → 动效只留渐入）；密度 4（参数型采购，一屏要看到规格 → 首屏放参数卡）；严肃度 4（高客单长周期 → 不用插画与圆角大于 4px 的按钮）。流派名决定底色，五刻度决定同一流派里偏向哪一头，和「个性化抓手」一起写进 `风格与字体方向.md`；**设计的方向单沿用这五个数，不另起一套**，设计认为某刻度该改时写归因回流，不默默改。

### 个性化抓手：防止一百家工厂做出同一个站

上面的流派表按公司类型查，输入相同输出就相同——一百家生产型工厂查出来都是国际企业风。流派只定底色，**这家公司长什么样，由抓手决定**。定完主风格后必须从下面四个来源**各提一条抓手**，每条都要落到一个具体的排版或视觉决定，写进 `风格与字体方向.md` 的「个性化抓手」一节。写不出四条就回去重读需求单，不许留空，也不许用「干净、专业、国际化」这类对谁都成立的词充数。

| 来源 | 从哪里提 | 要落到什么 | 例 |
|---|---|---|---|
| 产品几何与工艺 | 产品本身的形状、截面、结构件；表面处理与材质；加工工艺 | 全站母题（SVG 线稿、纹理、分隔线）；色板里至少一个颜色取自产品或表面处理；型号排版 | 紧固件：内六角截面做图标母题，螺纹节距做分隔线节奏；发黑 = 近黑、达克罗 = 银灰进色板 |
| 公司历史与数字 | 成立年份、设备台数、产线、全检方式、出口国家数 | 首屏讲哪一句、Counter 放哪四个数、About 的叙事顺序 | 2009 年 + 14 台冷镦机 + 3 台光学筛选机全检 → 首屏讲「全检」而不是「20 年经验」 |
| 目标市场审美 | 需求单里的目标市场优先级 + `references/风格与字体.md` 的市场修正 | 首屏结构（参数先行还是场景先行）、CTA 措辞强度、留白与饱和度 | 德国买家 → 首屏放参数卡、CTA 用 Request a Quote；美国 → 首屏放应用场景、CTA 更直接 |
| 你提名的参考站 | 需求单里你写的「喜欢它哪一点」的原话 | 翻译成一个具体版式决定，不是形容词 | 「bossard 找东西方便」→ 导航第一层按标准号分类 + 参数表可切换规格 |

每条抓手一行：**来源 → 事实（出处题号）→ 落到的决定**。设计据此做，并要在决策说明里自查「换成别家公司这个设计还成不成立」——成立就是没用上抓手。

字体按四句话定：**风格定字族、背景定字重、页面定层级、产品定点缀**。全站不超过两种字族加一种等宽点缀；参数表数字必须等宽（`tabular-nums`）；深色底上正文字重加一档且不用 300 以下细体；具体字体名与各档参数查参考文件。

## CTA 节律与定稿自查

### CTA 节律规则

一个页面只有一个转化目标，全页的 CTA 都指向它（询盘站是“提交询盘 / 获取报价”）。按钮文案全站统一，不要一处叫“提交工况选型”、另一处叫“立即询盘”、第三处叫“联系我们”。

CTA 出现的位置有固定节律：首屏一次（主按钮 + 次按钮）；页面中段在**证据之后**出现一次（看完产能数字、证书或案例，才有理由让人行动）；页尾一次，作为收束区，紧贴页脚。三次之外的转化入口只允许是粘性询盘条或浮动 WhatsApp，它们不占版面。

硬性规则：**两个 CTA 大区不能相邻**。如果发现页面里“不确定选哪个型号”之后紧接着“把工况告诉我们”这类连续两块，只保留一块——通常留页尾那块，把中段那块改成证据内容（参数表、案例、流程图）或直接删掉。导航栏的“询盘”按钮算首屏 CTA 的一部分，不额外计数。

每个 CTA 大区的文案不能重复。中段 CTA 讲“你的问题我能解决”（例如“不确定选哪个型号？工程师帮你核算”），页尾 CTA 讲“现在开始的成本很低”（例如“提供三个参数，24 小时内回复”）。同一句话出现两次，就是没想清楚这一块为什么存在。

次按钮要给“还没准备好询盘的人”一条路：查看选型指南、下载目录、看案例。不要两个按钮都是表单入口。

其余的 AI 建站惯性毛病（区块节奏、空洞形容词、图标堆砌、编造数字、内容重复、假 FAQ、页脚塞满、中式英语、字体没有行业感）逐条对照 `references/公司分型速查与自查.md` 排查。审完在方案里加一行“CTA 与区块节律检查：通过 / 需调整”，列出要删掉或合并的区块。

## 特殊情况处理

下面这些情况在真实项目里比“资料齐全”更常见。原则是：资料少不等于不能判断，判断可以带假设；素材差不等于不能设计，风格可以降级；但永远不编造、不用网图、不冒充。

| 情况 | 怎么判断 | 怎么办 |

## 判断时的提醒

- 站型定错，后面全错。先花时间在分型上，再谈风格。丢过来一个网址时，先看站、再定性、再出方案。
- 默认克制。B2B 站的动效上限是品牌站的一半，每一处动效都要能回答“它让采购更快看懂了什么”。
- 素材决定风格上限。没有专业拍摄就不推荐极简或摄影驱动，那会让页面显得空。
- 首屏定位句永远是“产品 + 买家类型 + 一个可验证的信任点”，不是“专业制造商”。没有可验证的信任点就用 `[待确认]` 占位，不要编一个。
- 询盘链路（表单到邮箱、WhatsApp、thank-you 页）比任何视觉都优先，方案里必须提到。
- 移动端和加载速度写进技术清单的硬约束，目标市场在东南亚、拉美、非洲时尤其。
- 方案里不要只扔技术名词，每个技术用一句“效果 + 好处”解释，让拍板人也看得懂。
- 混合站只允许一条主线，方案里明说另一条是次级入口。
- 一个页面一个转化目标，CTA 只在首屏、证据之后、页尾三处，两个 CTA 大区不能相邻，按钮文案全站统一。审 AI 页面时先数按钮。
- **需要你回答的问题全站合计不超过 5 个**，集中放在第六节并记进 `_内部/待用户决定.md`，经 PM 一次问完。超过 5 个说明有些问题该由假设清单承担，不该丢给你。
- 资料少就带假设出方案，不停工等资料；没有图就降级风格、分三级过渡、写补拍计划，永远不用网图、不冒充。
- 旧站有 logo 就把文件取下来用，不自绘、不改英文字标；只能重制时是描摹不是重画，并排要能认出是同一个标。品牌 logo 和跑马灯上合作买家的 logo 是两回事。
- 参考文件是弹药库不是清单：必须满足与明确禁止两层照做，形态那一层留给设计发挥，偏离了写归因就行。别把每个项目的导航和卡片做成同一个样子。
- 你现有的资料或旧站面向国内时，以出海目标市场风格为主导：结构、视觉、叙事都按目标市场重来，国内资料只用来取事实；没有明确目标市场按英文国际站默认。
- 建议的所有内容都能被 Google 和 AI 搜索读取：关键标题和参数放在真实 DOM 文字里，不藏在图片和动画中。
