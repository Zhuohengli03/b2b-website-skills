# 参考 · 旧站体检：类型全表、体检记录清单、迁移台账规则、单独跑的七段模板

从 SKILL.md 第一步「旧站类型 / 品牌资产取回 / 体检记录 / 迁移台账 / 旧站体检单独跑时」原样搬入；正文留压缩版与指针。

## 开工前先判旧站类型：决定「能迁什么」（全表）

打开旧站后、动手取资产和体检之前，先判它是哪一种——这一步决定能抓到什么、能导出什么，后面的保留 / 重做 / 推倒都建立在「能迁什么」之上（参考 boyang-hu/website-rebuild-skill）。判不出来就按最保守的一档（只能抄）走。

| 旧站类型 | 怎么认 | 能迁什么 | 怎么迁 |
|---|---|---|---|
| 静态站 / 普通 CMS 可访问 | 页面源码完整、图片 URL 可直接打开、无登录墙 | 整站：HTML、原图、PDF、URL 结构 | 整站抓取进 `_内部/抓取/`，原图按页面归档 |
| WordPress 可登录 | `/wp-admin` 可登、你有管理员账号 | 全部内容与媒体库、分类、URL、SEO 插件里的 title/description | 你导出 WXR + 媒体库打包；拿不到账号则退回上一档整站抓取 |
| 阿里国际站 / Made-in-China / SaaS 建站（Wix、Shopify 展示站等）不可导出 | 域名是平台子域或模板站、后台无导出项 | 只有事实：产品名、参数、描述、证书图、公司数字；版式与 URL 不迁 | 逐页抄录事实进事实清单，图片只取原图分辨率够的；URL 不做 301（平台域名不归你们公司） |
| 已死（域名过期、超时、证书失效） | 打不开、过期页 | Wayback 里残留的文字与低清图、Google `site:` 的收录 URL 清单 | 走 Wayback Machine 与 `site:`，见「特殊情况处理」；抓到的 URL 清单给后端做 301 |

判完在方案「二、旧站体检」第一行写明类型与「能迁什么」，再谈结论。类型不同，下面的 `旧站迁移台账.csv` 的「去向」列分布会完全不同——SaaS 站多数 URL 的去向是「删除」且无 301，这是正常的，不要为了凑保留而硬迁。

## 品牌资产取回（先于任何评价）

**第一件事是品牌资产取回，先于任何评价**，而且不管体检结论是保留、重做还是推倒都要做——推倒说的是结构和内容，不是品牌身份。旧站是资产来源，不只是批判对象。

- 从 header 的 `<img>` 取 logo 的 src，**直接下载原文件**；顺带取 favicon（常有更干净的纯图标版）；试 `/logo.svg`、`/logo.png`、`/images/logo.*`、`/uploads/*logo*` 这些常见路径。
- 记录：格式、像素尺寸、是否透明底、是否矢量。拿到矢量就不用再问你。
- 从 logo 与旧站吸主色，记 HEX；从旧站 CSS 取中英文字体栈。
- 记下 slogan、公司名的中英文写法、产品命名与型号规则、已有的图形符号。
- 全部存进 `_内部/00-资料/品牌资产/`，进素材清单，作为交接载荷给设计。取不到文件时，才记进 `_内部/待用户决定.md` 问你要 AI / EPS / SVG。


## 体检记录清单

然后按这张清单做体检记录：

- 首屏 5 秒内能不能看出“做什么的、给谁做的、凭什么信你”
- 导航结构（是否有 Products / Solutions / OEM / About / Contact，产品是否按用途或材质分类）
- 产品页有没有参数表、起订量、交期、应用场景、询盘入口
- About 是讲企业文化还是讲产能数字和证书
- 手机端是否正常、图片是否压缩、加载是否明显慢
- 每页有没有询盘/WhatsApp 入口，表单是否能提交
- 视觉：模板感是否严重、图是否是网图、色彩字体是否杂乱
- 技术栈线索（WordPress / 阿里国际站模板 / SaaS 建站 / 老式 table 布局）
- 收录情况：Google 搜品牌名能否搜到，站点标题是不是“XX Co., Ltd”
- 面向谁：旧站是不是国内版（中文为主、“企业文化 / 荣誉资质 / 新闻动态”栏目、领导视察照、微信二维码、大红大黄满屏信息）。是的话，新站按目标市场风格重来，旧站只作事实来源，见“特殊情况处理”

旧站体检结论落成三类：**保留**（结构或内容可复用）、**重做**（结构不对但素材能用）、**推倒**（连素材都要重拍）。

## 旧站迁移台账：清单对账零缺口（全文规则）

有旧站就要出 `_内部/03-方案/旧站迁移台账.csv`，四列固定：**旧 URL / 去向（保留·合并·删除）/ 301 目标 / 从该页抽取了哪些事实**。

- **清单对账零缺口**：旧站每个有效 URL 都要有一行——来源是整站抓取的页面清单、站点地图、Google `site:` 的收录结果三者合并去重；少一行就是一个上线后 404 的入口，推倒的站也不例外。
- 去向只有三种：保留（新站有对应页，301 指过去）、合并（几页并成新站一页，301 都指那一页）、删除（无对应页，301 指最近的分类页或首页；平台子域不归你们公司的写「无法 301」并注明原因）。
- 「抽取了哪些事实」写的是数字、证书、设备、型号、案例这类可证事实的条目名，不复制正文；写进这一列的事实才能进文案的事实来源表，没写的视为没有出处。
- 这张表是后端配 301 的唯一依据，也是文案找事实的索引；QA 在旧站下线前会按它抽样验 301，所以 301 目标列写新站的最终 URL，不写「待定」。

## 旧站体检单独跑时（`b2b-run` 模式 A）：范围

你只给一个网址、还没决定要不要重做时，体检是一份**判断加证据**，不是方案。范围：

- **可以抓全站**：先读 sitemap 和 robots，再抓页面（`scripts/crawl-old-site.mjs` 可用）；报告里给有效 URL 总数和按类型的分布（产品 / 新闻 / 信任页），但**不出 `旧站迁移台账.csv`**——「去向」和「301 目标」要等新站结构定了才有，那是模式 B 第 2 步的事。
- **每条问题都要有证据**：引用原文、标签、文件大小、URL；能实测的实测（图片总量、视频体积、表单字段、Schema 原文、hreflang、sitemap 覆盖）。移动端能用 `scripts/check.mjs --online --shots` 或 Playwright 截图就截，截不到写「未实测」，不猜。
- **只取品牌资产，不做方案**：logo 文件（能下就下，注明是位图还是矢量）、主色 HEX、字体栈、公司名与 slogan 的英文写法。不做分型、站型、技术选型、风格方向，那些等需求表。
- **不向用户报时长**。要么直接出报告，要么说清卡在哪（打不开、被墙、要登录）。
- 产出只有一份：当前目录的 `旧站体检报告.md`，不建 `_内部/`。
- 不发测试询盘给真实企业；表单到达一律写「未实测」。

## 旧站体检报告：固定七段模板（≤120 行）

报告固定七段，老板 5 分钟能读完：

```
# <公司名> 旧站体检 · <日期>
旧站：<URL> · 范围：只做旧站评估，不含方案、文案与设计

## 一、旧站类型与「能迁什么」
类型（静态可抓 / WordPress 可导出 / SaaS 只能抄 / 已死走 Wayback）+ 一张表：资产 / 状态（可抓·需后台导出·取不到）；
末尾一行：有效 URL 共 N 个（产品 a / 新闻 b / 信任页 c / 其它 d）；品牌资产：logo <位图或矢量> · 主色 <HEX> · 字体 <栈>。

## 二、结论：保留 / 重做 / 推倒
一句话结论 + 两句话说明为什么不是另外两档。

## 三、问题清单（按对询盘的影响排序，5–10 条）
每条：**一句话结论加粗** + 证据（原文 / 标签 / 数字 / URL）+ 采购看到时的反应。技术 SEO 的细项合并成一条，下面用小列表。
英文硬伤（拼写、直译、截断）单独一段，列原文和应改成什么。

## 四、做得对、值得留的
真差异点、能复用的素材、已经做对的技术项。素材门槛是否达标写一句。

## 五、未验证项（不做结论）
表单到达、移动端实机、收录与排名等，写明为什么没验。

## 六、要你确认的（5 条以内）
只问改版必须先定的：口径冲突的数字、主攻市场、对外邮箱、后台能否导出、logo 源文件。

## 七、下一步
二选一：① 填 `templates/建站需求表.md` 全量跑；② 只要这份报告。
```

「问题清单」里的每一条必须指到具体页面和位置；「采购看到时的反应」写具体后果（信任归零、搜不到、打不通电话），不写「不够现代」「不好看」这类没法行动的话。
